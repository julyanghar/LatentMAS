### 判决（诚实版）

1. **Text-MAS 是灾难**：四段文字接力比单模型掉 **14-16pp**（双 backbone 一致）——复现并放大了 L²-VMAS 的"文本 VMAS 跌破单体"现象。根因与盲探针一致：视觉信息每过一次文字瓶颈就损失一截。
2. **Latent-MAS 基本保住单模型水平**（−2pp 量级，Qwen3-VL/MMStar 上甚至 +0.4）：**KV 通道让 4-agent 链条"近无损"**——这与 A1 的 X≈U 完全自洽（通道无损 → 角色不添新信息时 MAS≈Single）。
3. **主卖点是通道对比而非"MAS 超越单体"**：Latent vs Text = **+12~14pp**。在"角色不引入新信息源"的对称设计下，MAS 本就不该无中生有——诚实表述："latent 通道把多智能体协作的通信税从 −15pp 降到 ≈0"。
4. **M1 零载荷在完整 4-agent MAS 中第四次复现**（m=0 ≈ m=10，两 backbone 均 n.s.）。

## C1-rev — 2026-08-04 修订：新增 Text-MAS-sighted 臂 + 官方判分口径

> **为什么做**：原 `text` 臂**只有 Planner 看图**（docstring 明写），而文献的标准文本 VMAS（L²-VMAS 附录 D.1）是**每个 agent 都拿到「文字问题 + 视觉输入」**。所以原主表的 `Latent−Text` 差距可能被我们自己的设定放大。
> **判分口径同步修正**（用户 2026-08-04 批准）：GQA 主口径改**官方 exact match**（[官方 evaluate 页](https://cs.stanford.edu/people/dorarad/gqa/evaluate.html)："1 point if the predicted answer p matches a"），原宽松匹配（exact/prefix/包含）作附加列并报；MMStar 保持严格档（等价 VLMEvalKit `exact_matching`）+ 报抽取失败率。

**Qwen3-VL/MMStar：textsighted − Single = +0.9pp → 落区间① → 原 text 臂确被"下游盲"设定削弱。**
3/4 格落区间①（≥ Single−3pp），1 格（Qwen3-VL/GQA）落区间②。**分歧必须在论文中明写。**

1. ⚠️ **主张必须改写**：「Latent 通道把通信税从 −15pp 降到 ≈0」这个表述**只在"下游盲"设定下成立**。一旦下游能看图，优势塌到 **−4.7 ~ +9.9pp，且两个 MMStar 格为负**。

2. **"下游能否看图"是比"通信介质"更强的变量**：它单独解释了原 Text 臂 −12~25pp 中的大部分。
3. ⚠️ **Qwen3-VL/GQA 的 −17.6 是真实掉分，不是判分伪影**（已诊断：最宽松口径下仍 −14.7pp，错例含 `gold=yes→ans=no` 这类真实翻转）→ **四轮讨论在简单感知题上会把对的答案聊反**。与文献一致（CoT 在多模态上平均为负；精选 8.4 帧打赢均匀 180 帧）。
4. **判分口径的臂间偏差已量化**：GQA 宽松匹配给话多的 text 臂送 **8.9pp**、给 single 只送 **0.6pp**；MMStar 严格档下 text 臂 **5.8%** 抽不到 ABCD、single 只 **1.3%**。**两个方向相反的偏差同时存在**，故双报口径。

### 与文献的对表（2026-08-04 拓扑调研）

⚠️ **原以为"我们的 text 臂弱于文献标准"，这个说法对「角色分工型接力」是错的**：调研核实**8 个角色分工接力系统里 7 个都是"头部 caption 一次、之后盲推"**（MAPS 代码层铁证：`InterpreterAgent.call_LMM` 带图，`Aligner/Scholar/Solver.call_LLM` 签名里没有 image 参数）。**只有 Insight-V 让每个 agent 都保持多模态。**

**一句话总纲**：LVAgent 是"**三个全能选手 + 两个代码裁判**"的结构——没有专职分工的角色，三个 VLM
每人把五种活全干一遍；真正的"协调者"不是 LLM，是两段纯代码（投票早停 + 评分淘汰）。

## 一、角色清单

### LLM 角色（3 个执行 agent，每人身兼五职）

| Agent | 对应模型（checkpoint） | 规模 | 加载处 | 特殊处理 |
|---|---|---|---|---|
| intern_8b | InternVL2.5-8B | 8B | all_model_agent.py:46 (`InternVL8B`) | `do_sample=True`（有随机性）；平分淘汰优先级第 1（先死）；评分 JSON 崩坏时默认分 6 |
| intern_78b | InternVL2.5-78B | 78B | all_model_agent.py:196 (`InternVL78B`) | `do_sample=True`；淘汰优先级第 3（最后死）；默认分 8（**大模型先验**） |
| llava_72b | LLaVA-Video-72B | 72B | all_model_agent.py:348 (`Llava72B`) | 贪心解码；淘汰优先级第 2；默认分 7 |

阵容在 discuss_final_lvbench.py 尾部硬编码实例化。仓库另备未启用的 Qwen 包装：`Qwen72bAgent`(:394)、
`Qwen7bAgent`(:453)、`Qwen2_5_7bAgent`(:512)——换阵容的现成接口。

**每个 agent 轮流扮演的五个功能角色**（同一权重，不同 prompt）：

1. **侦查判断员**（decide_watch prompt）：看 4 帧+字幕，回答 Yes/No——"这题需要看全片吗"；
2. **情报员**（info prompt）：写 ≤50 词的关键信息 K_i（第 2 轮起改为从讨论历史重生成）；
3. **答题员**（answer prompt）：拿 16 帧+字幕+选择题，只回一个字母；
4. **辩护律师**（reason prompt）：为自己的答案生成推理链；
5. **评审员**（discuss prompt）：给包括自己在内所有人的推理打 1-10 分，输出 JSON。

### 非 LLM 角色（代码与小模型）

| 角色 | 实现 | 干什么 |
|---|---|---|
| **检索器** | ASP-CLIP（CLIP4Clip 架构+时序 transformer 头；checkpoint 未发布） | 视频切 6 块×各随机采 16 帧，打分 Sim=CLIP(帧,K_i)+CLIP(帧,Q)，**argmax 取一块**供答题（代码 `get_max_frame_block`；论文写的 0.8 阈值多选在代码中不存在） |
| **投票裁判**（代码） | 主循环 | 三人答案 ≥2 票一致 → 早停定案 |
| **淘汰仲裁**（代码） | agent_back_process | 汇总互评总分，最低者出局；平分按硬编码优先级 [8b→llava→78b] 淘汰 |
| **终局规则**（代码） | 主循环 | 三轮皆无共识 → 最后幸存者独答定案（**不是投票**） |

**关键结构事实：系统里没有"聚合者 LLM"**——不存在一个读别人产出后做最终综合判断的模型；
共识由代码计票产生，无共识时由淘汰赛收敛到一人。

## 二、角色关系（一题的生命周期）

```
                    ┌────────────────────────────────────────────┐
                    │ R1  三个 agent 并行、互不通信:                │
 视频+字幕+题 ──────►│  侦查判断(4帧) → 情报K_i → [检索器选块 或 全局 │
                    │  随机16帧] → 答题员出字母                      │
                    └───────────────┬────────────────────────────┘
                                    ▼
                          投票裁判: ≥2票一致?
                             │是            │否
                             ▼              ▼
                           出答案   ┌──────────────────────────────┐
                                   │ Reflection(首次进入互相看见):    │
                                   │ 各自当辩护律师 → 互当评审员打分  │
                                   │ → 淘汰仲裁踢掉总分最低者         │
                                   │ → 幸存者读讨论史(含被淘汰者答案+  │
                                   │  "该理由不可信")重生成K_i        │
                                   └──────────┬───────────────────┘
                                              ▼
                    ┌────────────────────────────────────────────┐
                    │ R2  两个幸存 agent 重新检索+答题               │
                    └───────────────┬────────────────────────────┘
                                    ▼
                          投票裁判: 2票一致? ──是──► 出答案
                                    │否
                                    ▼
                          再淘汰一人 → R3 幸存者独答 ──► 出答案
```

通信介质与拓扑：**R1 完全无通信**（三路独立）；Reflection 起为**全连接文字通信**（答案+推理+评分
+淘汰通报全部以自然语言文本进入彼此 prompt）；无任何视觉内容在 agent 间传递（每人各自采自己的帧）。

## 三、信息流细节（谁读谁的什么）

| 发送方 → 接收方 | 内容 | 介质 |
|---|---|---|
| 检索器 → 答题员(本人) | 选中块内的 16 帧 | 像素（仅限自己） |
| 律师 i → 评审员 j（全对） | 答案+推理链 | 文字 |
| 评审员们 → 淘汰仲裁 | 分数 dict | JSON |
| 淘汰仲裁 → 幸存者 | 讨论史（各家答案/理由/分数 + 被淘汰者及"理由不可信"标注） | 文字（history prompt） |
| 幸存者的新 K_i → 检索器 | 下一轮检索 query | 文字 |

## 四、增益来源定位（论文消融 + 代码互证）

裸三人投票（去 Perception 去 Reflection）≈ 最强单成员水平 → **异构集成本身贡献 ≈0**；
真实增益 = 检索器把 16 帧从"全局盲采"变"按题定位"（Perception）+ 淘汰赛过滤坏推理（Reflection）。
对同质化复现的含义：换成 3×同一模型（不同 seed/帧子集）不动这两个增益来源——详见 doc17 §4。

## 五、与我们 G 系列薄壳的结构对照（一行版）

G1/G2=固定分段+专职侦察+**有聚合者 LLM**+单轮；LVAgent=不分段+检索定位+全能选手+**无聚合者**+
多轮淘汰。两者恰好互补覆盖了"分工 vs 检索""聚合 vs 共识"两个设计轴——门 2.0 同场竞技即出答案。

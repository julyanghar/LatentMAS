## 一、VideoHV 原始工作流：一场四幕剧

### 演员表

| 角色 | 干什么 | 本地扮演者 |
|---|---|---|
| **出题人** | 给每个选项立"假设"（这个选项若是真的，视频里应该发生什么） | Qwen3-8B |
| **判官** | 给假设打"区分度分"，并提炼一条**线索**（去视频里查什么才能区分它们） | Qwen3-8B |
| **验证员** | 主角。拿着线索去视频证据里核实——**这是唯一直接消费视频证据的角色** | Qwen3-8B |
| **选答人** | 读验证轨迹，选出最终答案 | Qwen3-8B |
| 幕后摄影师 | caption 工具：验证员点名要看哪几帧，它现场看图写描述 | Qwen3-VL-8B |

### 开演前备好的三样资产

1. **地图**：180 条逐帧 caption（原装 = LaViLa 模型写的，一帧一句短句）；
2. **摘要**：把 180 条压成 4 段的剧情梗概（原装 = GPT-3.5 写的）；
3. **帧图**：180 张 1fps 抽出的图片（给摄影师现场看）。

### 剧情（一题的完整流程）

```
① 出题人 读【摘要】 → 每个选项立一条假设
      └─ 只立出 1 条（其他选项明显不靠谱）→ 直接交卷，后面全跳过（early-exit）
② 判官 读假设+【摘要】 → 区分度分 + 一条线索
      └─ 分太低 → 打回重立假设
③ 验证员 拿线索 + 一次性通读【180 条地图】 → 找证据
      └─ 证据不够 → 喊"给我看 148-152 帧"（≤5帧，≤2轮）
           └─ 摄影师看图写描述递回来（【工具返回】）
      → 结论：verified / partially / not_verified
④ 选答人 读验证轨迹+假设+【摘要】 → 最终答案
⑤ not_verified → 回到① 重来（最多 3 轮）
```

真实跑通的一题（刺绣题）：4 次 LLM 调用、139 秒、工具调用 **0 次**（地图够用就不喊人）、答对。

### viewer→reasoner 的三条文字通道（latent 能切的位置）

| 通道 | 内容 | 谁在读 | 每题必经？ |
|---|---|---|---|
| 摘要通道 | 4 段梗概 | 出题人/判官/选答人 | 是 |
| **地图通道** | 180 条逐帧 caption | 验证员 | 是（early-exit 除外）← **分支二的刀口** |
| **工具通道** | 点名帧的现场描述 | 验证员 | 否（模型自己决定调不调）← **分支一的刀口** |

## 二、分支一 `tool-channel`：刀切在"工具返回"

**改哪**：验证员喊"给我看 148-152 帧"之后，摄影师递回来的**那段话**。地图（LaViLa 原样）、摘要（GPT-3.5 原样）、其余三个角色一个字不动——它们在五臂间是完全相同的常量。

| 臂 | 摄影师递回来的是 | 一句话 |
|---|---|---|
| A | 文字描述 | 基线：印刷体 |
| T+ | 同一段话，每个字带 top-64 犹豫（软嵌入） | 只多"犹豫"，别的全同 |
| D | 同样的文字，但验证员换成 Qwen3-VL 来当 | 同卷换考生 |
| C | 不写字了，直接把那几帧**照片**递进对话 | 看原件 vs 看转述 |
| A′ | 摄影师**先看过题目**再写描述 | 先知转述 |

**两个特殊安排**：
- **强制每题至少调一次工具**（机械强制：首轮预填 `<tool_call>`，全臂同一机制）。为什么：实测有题 0 调用——不强制的话被测通道很多题根本没被使用，比较无从谈起；
- 额外跑一条 **T-A0 自然臂**（不强制的 A 臂），记录真实调用率，报告里如实标注"以下效应是强制调用条件下的"。

**T+ 的分布哪来的**：工具是运行时现场调的，caption 当场生成——生成那一刻顺手把每个字的 top-64 候选拿走（vLLM 返回 logprobs），**不需要任何离线预生成**。

## 三、分支二 `map-channel`：刀切在"180 条地图"

**改哪**：验证员开场一次性通读的那份全图地图。工具通道保持文字、所有臂照常能调（常量）；其余角色不动。

**先要做一件工程**：地图必须用我们自己的 Qwen3-VL **重新写一遍**（离线，500 视频 × 180 帧）。为什么：LaViLa 的字是别人写好的成品，**没有"犹豫"记录**——T+ 要的 top-64 分布只有自己生成时才拿得到。顺带钉死单句短风格（每条 ≤32 token），防止地图膨胀撑爆 16k 上下文（审察坑）。

| 臂 | 验证员读到的地图 | 一句话 |
|---|---|---|
| A | 新地图，文字版 | 基线（注意：分数会和 LaViLa 版不同，分支内自成参照系） |
| T+ | 同一份地图，caption 内容 token 换软嵌入（`frame N:` 前缀保持硬） | 整份地图带犹豫 |
| D | 同一份文字地图，验证员换 Qwen3-VL | 同卷换考生 |
| C | 不给字了，直接给**同样那 180 帧的原图**（统一缩到 384×288，视觉 token 恰 19,440） | 看原片 vs 看地图 |
| A′ | 写地图前先看过题目的"先知版" | 先知地图 |

**摘要也要重生成**（Qwen3-8B 从新地图写，只读普通版目录）：摘要是地图的下游产物，地图换人写了摘要还是旧的会内容打架；但注意 A′ 臂**只换地图不换摘要**（摘要文件逐字节对比锁死），保证 A′−A 只测"先知"一个变量。

## 四、两分支对比一眼看

```
                 ┌──────────── 出题人 ─ 判官 ─ 选答人（永远不动）
                 │                  读【摘要】
   viewer 侧     │
  ┌─────────┐    │   【地图】180条 ──→ 验证员  ←── 刀口② map-channel
  │ Qwen3-VL │────┤                    │
  │ (+LaViLa)│    │   【工具返回】 ←──── 喊"给我看N-M帧"
  └─────────┘    │        ↑
                 └────────┴────────────── 刀口① tool-channel
   不动的文字：题目/选项/模板/线索/取帧请求（控制通道永远是字）
```

| | 分支一 tool-channel | 分支二 map-channel |
|---|---|---|
| 刀口 | 工具返回（按需、题目相关、短） | 全图地图（每题必读、最大载荷 ~2k token） |
| 地图 | LaViLa 原样（常量） | Qwen3-VL 重生成（实验对象） |
| top-64 来源 | 运行时现场取 | 离线资产（90k 帧，≤4 卡并行生成） |
| 摘要 | GPT-3.5 原样 | Qwen3-8B 重生成 |
| 工具 | 实验对象 + 强制≥1调 | 保持文字（常量） |
| 效应预期 | 更小但更干净、更贴"接收方决定看什么" | 更大（载荷大、题题必经） |
| 先做 | ✅（无重资产，最快出结果） | 资产生成并行在后台 |

两分支跑**同一份 500 题单**，各自内部做五个减法（T+−A 主假设；C−D、A−D 死刑条款；A′−A、C−A 描述性）；跨分支只做逐题双差，不把差异归因到"刀口位置"（因为资产/强制制度也不同）。

## 五、随分支顺手修的"跑得算数"问题（全臂常量，不是实验变量）

这些是审察+验真发现的上游坑，不修的话数字好看但结论是假的：

1. **8 处残留温度清零**（[verifier.py:118,181](/home/yilin/VideoAgent-LatentMAS/video_hv/verifier.py#L118)、[vision_tools.py:76](/home/yilin/VideoAgent-LatentMAS/video_hv/vision_tools.py#L76)、[openai_stages.py](/home/yilin/VideoAgent-LatentMAS/video_hv/pipelines/egoschema_openai/openai_stages.py) 五个阶段各一处）——配对逻辑全靠"相同输入说相同的话"，带温度=比谁运气好；
2. **工具返回改"原话"**：上游把模型生成拆行、去编号、再打包成 JSON（[vision_tools.py:78-84](/home/yilin/VideoAgent-LatentMAS/video_hv/vision_tools.py#L78-L84)）——T+ 的犹豫只存在于原话上，装盘后对不上号；全臂统一吃原话；
3. **帧数上限统一 5**（schema 写 20、prompt 写 5、代码不管——统一裁剪、requested/served 双落盘）；
4. **随机兜底加种子留痕**（上游异常直接 `randint` 且不留痕，[runner.py:196](/home/yilin/VideoAgent-LatentMAS/video_hv/pipelines/egoschema_openai/runner.py#L196)）+ 逐题落盘断点续跑（上游跑完才写盘，中途崩全丢）；
5. **server 三开关**（top-64 上限/VL 工具解析/软嵌入接收——不开则 D/C 臂静默退化成随机猜）；
6. **两张门卡**：E0 已过（手工模板=官方模板逐 token、one-hot 软嵌入=文字逐 token、工具解析两端一致——"自己组装的秤先拿砝码校准"）；E1（决定性冒烟）待跑。

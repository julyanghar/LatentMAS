## 1. 理想态

```
                     ┌─────────────────────┐
   视频帧 ──────────► │ viewer = 视觉模型     │
                     │ (Qwen3-VL-8B)        │
                     └──────────┬───────────┘
                                │  ⭐ latent，不是 caption
                                ▼
                     ┌─────────────────────┐
                     │ reasoner = 文本推理模型│ ──► 决定下一批看哪几帧 / 出答案
                     │ (Qwen3-8B-Thinking)  │
                     └─────────────────────┘
                                │  循环，最多 N 轮
```

**三条硬要求**：① viewer/reasoner 分离且 reasoner 是**文本推理模型** ② 建在**已有** workflow 上 ③ 在**多个**框架上有效。

**为什么坚持文本 reasoner**：VideoAgent 自己的消融——接收方从 GPT-3.5 换 GPT-4 值 **+11.4 分**，而文字通道加宽 10.3 倍只值 **+0.6 分**。**接收方推理力比通道重要约 19 倍**，换成 VLM 当 reasoner 等于自废这 11.4 分。

✅ **2026-08-05 拿到第二份独立证据**（MemDreamer [2606.07512](https://arxiv.org/abs/2606.07512) Table 6，我逐格核过）：LVBench 上**换感知模型只动 0.4 / 1.4 / 2.5 分，换推理模型动 10.0 / 12.1 分** → **reasoner 比 perceiver 重要约 4~30 倍**。同篇 Table 5 更直接：端到端下"模型的 AIME2025 推理力"与 LVBench 的相关性只有 R=0.702（p=0.052，不显著），**解耦后升到 R=0.897（p<0.01）**。**这一条硬要求是本计划里唯一被两篇独立论文正面支持的。**

**为什么坚持多框架**：把工作从"一个系统的 hack"变成"可插拔的通道"，并填 [Q&A/06 §4.2 空格 #7](../Q&A/06-latent-collab-design-space-and-brain-tool-edge.md)（这条线**没有共同 benchmark、没有 head-to-head 协议**）。

## 2. ⚠️ 为什么大概率要训练

### 2.1 实测的跨模型漂移（本机探针）

#### 2.1.0 这张表在回答什么问题

最省事的做法是：**viewer 看完帧、前向一遍，把产生的 KV cache 原样塞给 reasoner 当前缀，一个字都不生成。** 如果这样能行，整个项目不用训练。

问题是 viewer（Qwen3-VL-8B）和 reasoner（Qwen3-8B）**是两个不同的模型**。viewer 记的"笔记"，reasoner 读得懂吗？

打个比方——**两个人交接班，前一个人留下一本工作笔记**。交接要成功，得三件事同时成立：

| # | 交接班的条件 | 对应到模型 |
|---|---|---|
| ① | **本子插得进去** —— 笔记本规格（几页、每页几格）一样 | KV cache 的张量形状一致 |
| ② | **页码对得上** —— "第 37 页"在两人那儿指同一处 | 位置编码的算法一致 |
| ③ | ⭐ **字认得出** —— 同一个符号在两人心里是同一个意思 | 生成 K/V 的权重矩阵一致 |

**下面六行探针的结论：① 和 ② 过了，③ 没过。而 ③ 是唯一一个调参绕不过去、只能靠训练解决的。**

#### 2.1.1 逐行白话

| # | 探针 | 数字 | 白话 |
|---|---|---|---|
| ① | **KV 几何** | ✅ 36 层 / hidden 4096 / 32 Q 头 / **8 KV 头** / head_dim 128 / vocab 151936，**完全一致** | Qwen3-VL 去掉视觉部分剩下的"语言塔"和 Qwen3-8B 规格一模一样。**每层每个 token 产生的 K/V 张量形状逐位对齐，可以 1:1 直接装**，连 reshape 都不用。这是**唯一**的好消息，也是这条路值得试的原因 |
| ② | **M-RoPE vs 1D** | ✅ `max abs diff = 0.0` | 原先担心：Qwen3-VL 用**三轴**位置编码（t/h/w，因为图片是"面"不是"线"），Qwen3-8B 用**一维**，同一个 token 两边编出来的位置不一样，KV 转过去就错位。**实测这是伪问题**——对纯文字 token，三轴会**精确退化**成一维（三个轴取同一个数），逐位相减**一个 bit 都不差** |
| ③ | ⚠️ **`rope_theta` 不同** | ❌ **5e6 vs 1e6**，平均 cos **0.713** | RoPE 编位置的办法是"把向量按位置**转一个角度**"，转多少由底数 `theta` 决定——**theta 越大，同样的位置差转过的角度越小**，可以理解成**尺子的量程**。Qwen3-VL 用 5,000,000（为长视频设计的长量程尺），Qwen3-8B 用 1,000,000（短量程尺）。同一个位置 p，两边转的角度不一样，**位置越靠后差得越多**，实测**超过约 64 就基本对不上**（cos 0.713 ≈ 夹角 44°）。<br>✅ **但这条是确定性的、不用学**：知道两边的 theta，就能"按 5e6 反着转回去、再按 1e6 转过来"（§5.1 的"反旋+重旋"） |
| ④ | ⚠️ **k/v_proj 权重漂移** | ❌ **15–27%**，是 Qwen3 自身后训练漂移（**6–10%**）的 **2.3–2.7 倍**，随层加深**单调增大** | ⭐ **这才是真正的坎。** K 和 V 不是凭空来的，是 hidden state 乘一个矩阵算出来的：`K = h·W_k`，`V = h·W_v`。两个模型的 `W_k/W_v` **权重不一样**。<br>**参照系**：同一个模型自己在后训练前后（base→instruct）变了 6–10%；viewer↔reasoner 之间差 15–27%，**是那个的 2.3–2.7 倍**。<br>**后果**：viewer 算出来的 K 是"**用 viewer 的尺子量的**"，reasoner 拿到手会当成"用我的尺子量的"来解读——**读出来的是另一件事**。而且越往深层越离谱 |
| ⑤ | ⚠️ **端到端** | ❌ 真实 24-token 提示，**只过第 0 层**，V-cache 相对误差已 **31.9%**（cos 0.948） | 前四行是拆开测的零件，这一行是**装起来测**。拿一段真实提示、两个模型各跑一遍，**只看最浅、最该一致的第 0 层**——误差就已经三成。**第 0 层就这样，后面还有 35 层。**<br>自己验算一遍：两个向量若长度相同、夹角 cos=0.948，相对误差 = √(2×(1−0.948)) = **32.2%**，实测 31.9% → **长度基本一致，误差几乎全来自方向偏了 18.5°** |
| ⑥ | ⚠️ **chat 控制符最糟** | ❌ `<\|im_start\|>` / `<\|im_end\|>` 相对误差 **54% / 57%**，普通文字 token 只有 **16–20%** | 这两个是标记"**谁在说话、话说到哪**"的特殊 token。两个模型各自的 chat 模板训得不同，**这些 token 的表示漂得最狠，是普通 token 的三倍**。<br>**为什么这条特别恶心**：多智能体交接**每一次**都要经过这些 token——**最需要对齐的结构支架处，误差最大** |

#### 2.1.2 三句话结论

1. **插得进去**（①），**页码能算准**（②③，且③是确定性修正，不用学）。
2. ⭐ **但字读不懂**（④⑤⑥），而这只能靠**训一个 adapter** 解决——这就是 §2.2 和 §5 存在的理由。
3. **量级参照**：DroidSpeak 测过"朴素 KV 复用会掉 >50% 准确率"的区间，**我们的漂移已经超过那个水平**。所以不是"试试看能不能凑合"，是**已经知道凑合不了**。

### 2.2 一个比漂移更硬的障碍

> 视觉 token 经 projector 后确实落在 LLM 输入嵌入空间里。但**纯文本 LLM 的权重从未见过这些向量**。把视觉 latent 交给它，等于要求它**免费完成 BLIP-2/LLaVA 那个 projector 靠训练才学会的事**。

这条对"reasoner 是文本模型"是**结构性**的，调参绕不过去。

### 2.3 文献旁证

**每一个免训练 latent 方法都要求架构相同**；**每一个跨家族方法都训了转换器**；[空格 #4](../Q&A/06-latent-collab-design-space-and-brain-tool-edge.md)：**不存在零样本跨家族 KV 桥**。而**唯一被证明能把多智能体转成增益的机制，就是"训练过的通信模块"**（L²-VMAS +4.0 且 token 少 44%）。

## 3. ⭐ 阶段一：立论验证（**一行 latent 代码都不用写**）

### 3.1 VideoAgent 的真实循环

```
① 均匀采 5 帧
② captioner 给每帧写一句话           ← LaViLa，平均 7.2 词
③ reasoner 读【问题 + 这些句子】→ 答案 + 自信度(1/2/3)
④ 自信度 < 3 → reasoner 写"我还需要看到 XXX" → CLIP 检索匹配帧
⑤ 新帧句子加进来 → 回 ③
⑥ 最多 3 轮（实测 72.2% 的题至少回到 ④ 一次，73.3% 的自评说"报告不够用"）
```

**所有臂跑同一个循环，唯一差别在 ②③：reasoner 收到什么。**

### 3.2 五臂定义

| 臂 | reasoner | 第②步 captioner | 第③步 reasoner **实际收到** |
|---|---|---|---|
| **A**<br>现状 | **Qwen3-8B-Thinking**（无视觉塔） | Qwen3-VL 每帧写一句 | `问题 + "frame 45: 一个人在水槽边刷盘子" + ...` ← **纯文字** |
| **D**<br>控制组 | **Qwen3-VL-8B**（**不给图**） | 同上 | **与 A 逐字相同的文字**，只换了读它的模型 |
| **C**<br>杀手控制 | **Qwen3-VL-8B** | ❌ 不写 caption | `问题 + 【第45帧原图】+【第90帧原图】+ ...` ← **直接给像素** |
| **A′**<br>先知上界 | **Qwen3-8B-Thinking** | ⭐ **事先告知本题后续会追问什么**，写一份全答的长 caption | 纯文字，但是"能预知未来的人能写的最好版本" |
| **B**<br>我们的 | **Qwen3-8B-Thinking** | Qwen3-VL 编码这些帧，**不解码成文字** | 经 adapter 翻译的 **latent 向量** |

**具体例子**——题目 *"视频里这人先做了哪件事？A)洗盘子 B)倒水 C)擦桌子 D)开水龙头"*：

| 臂 | reasoner 看到的 |
|---|---|
| A | 文字："frame 1: 从碗里倒水 / frame 45: 把海绵放进水槽 / frame 90: 用海绵擦盘子" |
| D | **一模一样这段文字**（读它的是 Qwen3-VL） |
| C | **那三帧的原图**，自己看 |
| A′ | 更长的文字，因 captioner 被提前告知"会问先后顺序"："frame 1（最早）：倒水，水从碗流向水槽 / …" |
| B | Qwen3-VL 编码那三帧得到的 latent（人读不了） |

### 3.3 四个减法，各自回答一个问题

```
⭐ C − D    同一个模型，一个看原图、一个读 caption
           → 这才是「文字通道到底丢了多少」的干净测量（reasoner 能力被控住）

⭐ C − A    「干脆换个多模态模型直接看帧」总共值多少
           → 杀手控制：这个数若很大，"换模型"就解决了，要 latent 干什么

   A − D    同样读 caption，文本推理模型比 VLM 强多少
           → 验证「文本 reasoner 更会推理」这个前提（VideoAgent 说 +11.4）

   A′ − A   文字边因「不知道未来会被问什么」而丢的那部分
           → latent 能补这块；剩下的补不上
```

> **A 那一格没有"直接看帧"选项**：Qwen3-8B-Thinking 根本没有视觉编码器。**所以纯文本 reasoner 的天花板就是 A′。**

### 3.4 判死规则（预先写死，不得事后放宽）

| 观测 | 判决 |
|---|---|
| **C − D ≈ 0** | 看原图与读 caption 无差别 → **通道压根没丢信息 → 立论崩，止损** |
| **C ≥ A + 我们能指望的增益** | "换个多模态 reasoner"就解决了 → **立论崩** |
| **A − D ≤ 0** | 文本 reasoner 并不更强 → 应改用 VLM reasoner → **理想态作废**，退回"同模型双角色" |
| **A′ − A ≈ 0** | 预期缺口为零 → latent 能补的空间被压缩，需重新评估 |

**只有 C−D 显著为正、C 没高到吃掉我们的空间、A−D 为正，这个 idea 才成立。**

### 3.5 ⚠️ 一个必须同时记住的反转

**C 不是免费的上界**：它每轮每帧都付完整视觉编码。VideoAgent 平均 8.4 帧、72.2% 的题要重调 → **C 的算力可能是 A 的数倍**。

所以**即使 C 分数最高也不必然判死我们**：若 C 赢准确率但输成本，而 B 能拿到接近 C 的准确率 + 接近 A 的成本，仍成立。**但主张必须写成「帕累托前沿」，不能写「我们更准」。**

### 3.6 已有证据的方向（不乐观，所以更要测）

| 来源 | 结论 |
|---|---|
| 本项目 Phase1/2 盲探针 | X(KV) ≈ U(看图) ≫ T(文字)，**X−T = +9.8 → +17.8pp** ← 支持"丢很多" |
| **本项目 C1-rev**（2026-08-04） | ⚠️ **一旦下游能看图，Latent−Textsighted 只剩 +1.2 / −4.7 / +9.9 / −0.5** ← 上面那个 +9.8~17.8 主要来自"下游全盲" |
| **TAMA**（唯一直接测量） | 工具返回图 vs 返回 caption：**均值 +2.68，SE 1.37，p≈0.145，分不出与零** |
| **VideoAgent 自己的消融** | 文字通道加宽 **10.3 倍只买到 +0.6 分** |
| ⚠️⚠️ **MemDreamer**（2026-08-05 新读） | **纯文字图记忆在小时级视频上比"整段像素喂进去"高 +8.7 ~ +21.2 分**（LVBench：Gemini-3.1-Pro 78.2→**90.7**；Qwen3-VL-235B 63.6→**84.8**），上下文还小 41~124 倍 |
| ⚠️ **Sterner et al.**（2024） | 视觉上唯一跑过"caption vs latent 其余全固定 + 纯文本接收方"的论文：0-shot **caption 45.9 vs latent 41.4，caption 赢 4.5（p<0.01）** |

我们的数是"下游全盲"设定，TAMA/VideoAgent 是"问题条件化工具"设定——**后者更接近 VideoAgent 场景，且结论是"损失小到测不出"**。

> ⚠️ **2026-08-05 必须写进来的一句**：**六份证据里有四份指向"文字丢的没那么多"**。MemDreamer 那条尤其重——它说明**赢面主要来自上下文管理，不是通道保真**。
> **但 MemDreamer 的对照不干净**（它的端到端臂是"整段视频像素平铺进 240–784K 窗口"，感知侧是"10 分钟滑窗流式逐段"，**视觉吞吐量和上下文结构都不同 → 犯了我们自己的门槛 E4(d)**）。
> ⭐ **我们 §3 的 C 臂恰好是那个干净版本**：给 reasoner 的是**同一批被选中帧**的像素、文字臂是**同一批帧**的 caption。**这个对照没人跑过，判死点不变——但先验概率已经明确往不利方向移了，动手时要按"大概率证伪"来准备。**

## 4. 阶段二：1 小时判死免训练（实验 γ）

**为什么还做**：1 GPU 小时、无训练、无图像；**判死本身是可写的一段**（"我们测了，免训练在此不成立"比直接上训练有说服力）。

```
数据：GSM8K 200 条纯文本提示（无图 → 最有利情形）
A 参照：Qwen3-8B 自己 prefill、自己解码
B 朴素：Qwen3-VL-8B 无图 prefill 同一提示 → dump 逐层 K/V → 逐字装进 Qwen3-8B → 解码
C 修复：同 B，但 key 先按 5e6 反旋、再按 1e6 对接收方 1D 位置重旋
读数：① 逐层 K/V 相对误差 ② top-1 一致率 ③ 准确率
判死：B 崩且 C 救不回（top-1 < 90%）→ 免训练结束，进 §5
```

## 5. ⭐ adapter 具体怎么做

### 5.1 要解决三件事

| # | 问题 | 现状 |
|---|---|---|
| **形状** | 能否直接装进去 | ✅ **免费**：36 层 / 8 KV 头 / head_dim 128 **完全一致**，1:1 对齐 |
| **位置** | rope 底数不同 | ⚠️ 5e6 vs 1e6，key 必须**反旋 + 重旋**（确定性操作，**不用学**） |
| ⭐ **内容** | reasoner 从没见过视觉 token | ❌ **唯一需要"学"的部分** |

### 5.2 注入点——对纯文本 receiver 只有一个被验证过

| 注入点 | 谁做过 | 对我们 |
|---|---|---|
| (i) 逐层 KV 前缀拼接 | LatentMAS / LACO —— **但两端同架构** | ⚠️ **最危险**：reasoner 第 0..l−1 层从没见过这些，第 l 层却要拿它当 K/V。**纯文本模型上无先例** |
| (ii) 加性融合 | C2C | ⚠️ 同样问题，训练更重 |
| ⭐ **(iii) 输入层嵌入** | ⭐ **BLIP-2 / LLaVA / Frozen 这条线，已被大规模验证** | ✅ **推荐** |

> **为什么必须 (iii)**：BLIP-2 的 Q-Former 能让一个**冻结的纯文本 LLM** 理解图像，正因为它把视觉信息投到**输入嵌入空间**，让 LLM 用完整 36 层去处理。而 (i)/(ii) 要求 reasoner 在**中间层**接受一堆它前面各层从未参与生成的 K/V——**这在纯文本模型上没人做成过。**

### 5.3 ⚠️ 换成输入层注入，效率论证还成立吗？——成立，但理由不同

```
现状 A：captioner 要【生成】~150 个 caption token
我们 B：captioner 只【编码】，零 token 生成；reasoner 侧多 prefill m≈32 个 token

关键比值（8B/A100）：prefill 0.114 ms/token   vs   decode 10.46 ms/token   ← 差 92 倍
省：150 次 decode ≈ 1.57 s          付：32 次 prefill ≈ 3.6 ms
```

> ⭐ **效率优势来自"根本不生成文字"，不是"跳过层"。而 decode 比 prefill 贵 92 倍，所以换注入点几乎不损失效率论证。**

### 5.4 具体架构（推荐：Q-Former 风格，**读料**是 viewer 的逐层 KV，**载体**是输入层伪 token）

> ⚠️ **两条轴别混**（2026-08-05 澄清）：**读料**＝ adapter 从 viewer 取什么（我们取前 4~10 层 KV，多数先例取末层 hidden 或 ViT 特征）；**载体**＝以什么形式进 reasoner（我们取 m≈32 个**输入层伪 token**，与 NavGPT-2 / Latent Bridge / BLIP-2 谱系**同款**）。
> **→ "我们传 KV"这个说法从来不成立**，凡是据此写的差异化论证全部作废；同时 [Q&A/06 §4.2](../Q&A/06-latent-collab-design-space-and-brain-tool-edge.md) 那个"没人传过 VLM 逐层 KV"的空格**我们也不填**。详见 [03 §0.5](03-eight-risk-papers-explained.md)。

```
输入：viewer 编码这批帧后的中间表示（读料与层深均为扫描超参，见下方修订）
        ↓
结构：m 个可学 query token（m ≈ 32，对齐 BLIP-2 与 MACF 的 K=32）
        ↓ cross-attend 到那几层的 KV
        ↓ 2~6 层小 transformer（内部宽度 d=512）
        ↓ 线性投到 reasoner 的 d_model = 4096
        ↓
输出：m 个向量，当输入 token 塞进 reasoner 的 prompt
```

> ⚠️ **2026-08-05 修订：原「按 LACO 取前 4~10 层」的依据被识别为错置，读料改为双轴扫描。**
>
> **(1) 层深**：LACO 的"浅层最优"是**载体=直接 KV 注入**时的结论（防深层 KV 劫持接收方策略）；我们的机制是**训过的 adapter 主动读取**，不存在劫持，该规则约束不到读料。而"视觉信息在哪层"的证据指向**中层**——ViF drop study【复核，baseline 85.2】：丢浅层随机 100% → 30.5（信息平摊未加工）；**丢中层 unimodal 关键子集 100% → 25.3（−59.9，最致命，信息已浓缩进少数 token）**；丢深层任何 100% → 81.8~82.6（**−2.6~−3.4，视觉 token 已无所谓——内容迁进了其他位置**）。旁证：Latent Bridge 读第 24/36 层、MACF 读末层、eP-ALM 读 encoder 末几层，**没有一家读浅层**；我们 LMCache 侧实测"sink/浅层安全、中后层承载内容"同向。
> → **扫描 {浅 4–10 / 中 12–24 / 末层 / 多深度}，先验偏中层**；读深层时连文本位置一起读（内容已迁移）。浅层唯一的辩护是可截断 viewer 前向省算力——当可测旋钮，不当默认。
>
> **(2) 读料形式**：GQA 下 K、V 各仅 1024 维，是 4096 维 h 的**有损投影**——**信息上读 h 严格不亏**。选 KV 的真实理由是系统性的（KV cache 是服务栈里天然跨轮驻留的工件 + "重看不重编码"的效率叙事），不是科学理由。→ **扫描 {V-only, K+V, h}**。另：**K 被 RoPE 旋过而 V 没有**——K 的内容与位置纠缠，**优先读 V（位置另给）或先反旋 K**。

> ⭐ **(3) 输出头两个变体（2026-08-05，B 源自用户提案，【提案，未验证】——两臂平级对比，谁赢听数据，不预设 B 成立）**：
>
> | 变体 | 输出 | 一句话 |
> |---|---|---|
> | **A 自由向量**（原计划） | m 个任意 4096 维向量 | 表达力无上限，但落在 reasoner 没见过的区域（off-manifold 风险；我们 Phase1"两个世界"实测：视觉表示天然不住在词嵌入区） |
> | ⭐ **B 软词瓶颈**（vocab-simplex head） | `softmax(h·Eᵀ/τ)·E`。**逐步读**：h=adapter 内部向量(4096)；`h·Eᵀ`=对全词表 151936 个词各打一个点积分；softmax(÷τ)=打分变成非负归一的"配方" p；`p·E`=按配方把词嵌入加权平均回 4096 维。E=reasoner 冻结词嵌入(151936×4096)，**零新增参数**。τ→0 退化成最近词(one-hot)，τ→∞ 退化成全词表均值，中间=软混合 | 消息被强制为 reasoner **母语词嵌入的概率加权和** = **trained cross-modal CIPHER**。天生在流形上（off-manifold 异议按构造消失）+ 可解释性白送（每个伪 token 自带 top-k 词）+ τ 连续插值 caption↔latent |
>
> **两臂都训、正面对比**（不是先选一个）：**A≈B → 选 B**（白送可解释性，审稿更好过）；**A≫B → 差值=「超语言视觉信息」的实测大小，本身就是主图**。双赢结构。
> 📌 **不需要对 E 求逆**（2026-08-05 追问回填）：软词瓶颈是**前向参数化**（adapter 直接产出权重 p，消息=p·E），不是**分解**（给定 e 反求 p——那才是逆问题，且病态：4096 个方程对 151936 个未知数，严重欠定；E 非方阵无逆，伪逆系数带负号不是概率）。`h·Eᵀ` 就是一次注意力打分（Q=h, K=V=E），lm_head 每次生成都在做同款运算。⭐ **而且恰因不可精确求逆，格式才有约束力**：无约束线性组合能精确表示任何向量（秩 4096）＝零约束；限到概率单纯形才产生"只能用词典调色"的压缩——**调不出来的那部分就是 D0-d 要测的超语言信息**。同理 D0-d 的事后投影也非求逆而是**有损投影**（p·E≈e 不等于 e），这正是它只算下界的数学原因。
> ⚠️ **B 可能不成立的四种方式**（预先列全，作为它的判死清单）：① **容量不够**——视觉细节词典调不出来（表现为 A≫B；注意这对项目不算坏事，差值=超语言信息的实测证据）；② **熵塌缩**——跑向 one-hot（退化 caption）或均匀（恒定向量），**训练时监控熵 + 正则**，τ 要扫；③ **范数收缩**——凸组合必然把输出往全词表均值拉、熵越高范数越小 → 伪 token 可能在 reasoner 注意力里"声音太小"（VW 的 NormMatch 存在正因范数要紧），**监控输出范数/真实词嵌入范数比值**，必要时补可学标量增益；④ **两臂都输给 caption**——问题不在格式在整条路线，回 D0 判死。
> ⚠️ 与 D0-d 的关系：D0-d 的事后投影只是 B 的**下界**（训练后量化 vs 量化感知训练的区别）——**判"软词够不够"必须用穿过投影训练的 B 臂，不能只用事后投影**。

**参数量**：

| 组件 | 参数 |
|---|---|
| m=32 query（4096 维） | 0.13 M |
| 6 层 cross-attn transformer @ d=512 | ~19 M |
| 输出投影 512→4096 | 2.1 M |
| **合计** | **~21 M** |

**对照**：Latent Cache Flow **19.4M**（13MB / 300 步 / 单 A100 **4.5h**）· Vision Wormhole ~41M（400 步 / A6000 / **3–6 GPU·h**）· C2C **477.8M/对**。
→ 我们落在 LCF 量级，**约 5 GPU 小时一次配方**。

### 5.5 训练信号三选一

| 方案 | 目标 | 风险 |
|---|---|---|
| 重构式 | 让 reasoner 读 latent 后的 hidden 逼近读**完整 caption** 后的 hidden | ⚠️ **天花板 = caption**，学不出超过文字的东西 —— **与我们"文字有损"的立论自相矛盾** |
| 行为式 | 直接用下游答案对错 | 信号稀疏；SDE 实测"端到端 CE 有平凡解＝模型学会忽略通道" |
| ⭐ **对比式**（推荐） | 正样本＝本题 latent，负样本＝**别题 latent** | ⭐ **把 shuffle 对照写进训练目标**，从结构上禁止学成"触发器" |

**为什么强推对比式**：因果审计实测——**+10.00pp 的 latent 增益里有 +8.13pp 在"消息来自别的样本"时仍存在**，即**绝大部分增益不是内容特异的**。对比式是目前唯一能从机制上堵住这个的做法。

实践：**对比式为主 + 行为式为辅**（加权），并挂 **ΔL 早停**——每 N 步多跑一次 forward 算 $\Delta L = L(M_{\text{别题}}) - L(M_{\text{本题}})$，**500 步内不单调上升就杀掉配方**（零成本，把"一个配方一天"压到"1–2 小时"）。

|---|---|---|---|
| 1 | 传几层最好 | 前 1/4/10/36 层扫描 | 超参扫描 |
| 2 | ⭐ **m=32 够不够装下一帧的视觉信息** | **重构上界测试**：不接 reasoner，只测 m 个向量能否重建 caption 级信息 | 半天，**能提前判死** |
| 3 | rope 反旋/重旋是否正确 | 逐位数值比对（复用 B1 金标准测试） | 1 小时 |

| **6** | VideoAgent 全量评测（B 臂进 §3 那张表） | ~1 天 | 见 §7.1 |
| **7** | 第二个 host | 待评估 | 第一个 host 无效则不进入 |

> ⭐ **阶段 1–2、4 全部不需要 latent 代码，却能判死整个立论。这是本计划最重要的排序决定。**

### 7.1 主指标不能只报准确率

因果审计实测：latent 通信**总效应 −1.00pp**，却藏着 −6.17pp 的"消息存在效应"和 +5.17pp 的"内容效应"。**准确率可由方向相反的两块合成。**

必报（我们已有这套机器）：
```
主指标 CAG = 收到【本题】latent 的表现 − 收到【别题】latent 的表现
对照臂：零消息 / 随机消息 / shuffle 消息 / caption 消息 / 上界（C 臂）
```

### 7.2 效率账按三口径分开报

vs **caption 基线**（省掉 captioner 全部生成 token）· vs **单模型** · **墙钟 + 显存 + 吞吐**都要有（L²-VMAS 全文没有一个墙钟数字）。

| 原主张 | 推翻它的论文 | 后果 |
|---|---|---|
| "没人让像素发送方把 latent 交给独立挑选的纯文本 LLM 在多轮 agentic 循环里用" | **NavGPT-2**（ECCV 2024，[2407.12366](https://arxiv.org/abs/2407.12366)）：冻结 ViT-g/14 → 32 个 Q-former query + 线性投影 → **四个纯文本 LLM 互换、全程冻结**（FlanT5-XL/XXL、Vicuna-7B/13B），R2R 逐步循环 | 字面上**全中**。只能靠两个额外合取项活：**(a) 发送方是会推理的 agent 而非接收方的感知前端；(d) 接收方自己决定看什么** |
| "没有多模态论文跑过 caption vs latent 其余全固定 + 纯文本接收方" | **Sterner et al.**（Cambridge 2024，[2403.11317](https://arxiv.org/abs/2403.11317)）：**整篇论文存在的唯一目的就是这个 arm**，对照比我们更严（caption 由**同一个冻结 LLM 从同一份 latent** 解出） | 方法论不新，只有**设定**新。而且**结果对我们不利**：0-shot caption **45.9** vs latent **41.4（−4.5，p<0.01）**，latent 只在 Q+I 选例下小赢 +0.5/+1.5/+1.6 |

⭐ **必须插进 §3 的新判死点（优先级最高，因为它最便宜也最致命）**：

> **NavGPT-2 Table 5**：把导航策略网络拿掉、"force the LLM to take over the decision-making"，Val-Unseen **SR 67.52 → 21.46（−46.06）**，原文 *"a frozen LLM is incapable of inferring effective representations that indicate a correct action."*
>
> → **判死点 D0**（⚠️ 2026-08-05 拆成三级，见 [02 §C.4](02-navgpt2-and-sterner-explained.md)）：
>
> | 级 | 问题 | 不过怎么办 | 要训 adapter 吗 |
> |---|---|---|---|
> | **D0-a** | reasoner 能只凭 latent **复述**帧内容吗？ | 不能 → **看不懂**，桥设计错了，回 §5 重来 | ❌ 不用 |
> | **D0-b** | 给 1~2 道 in-context 示范后，latent 臂**追上** caption 臂了吗？ | 追不上 → **信息真没传到** → 止损 | ❌ 不用 |
> | **D0-c** | 这个 gap 随 adapter 训练**单调缩小**吗？ | 不缩小 → 训练目标选错 → 止损 | ✅ 要 |
> | ⭐ **D0-d**<br>反解阶梯（三臂） | 同一份伪 token 走三臂喂回 reasoner：**hard**=E[argmax(e·Eᵀ)]（最近词）· **soft**=softmax(e·Eᵀ/τ)·E（**投回词嵌入凸包，CIPHER 式软叠加**）· **raw**=e 原样 | raw≈soft≈hard → 文字装得下 → 止损；raw≈soft≫hard → 信息在叠加权重里，优势真但 **CIPHER 级通道可能就够**（要答"为何还要 21M adapter"）；**raw≫soft → 信息在词嵌入凸包之外，超语言的最强证据** | ⚠️ 要（粗训 adapter 即可；τ 要扫；用**输入嵌入矩阵**而非 lm_head，先查 `tie_word_embeddings`） |
>
> **为什么这么拆**：Sterner 的三条线索（0→1 shot 向量臂跳 +9.1 而文字臂只跳 +4.1；向量臂在颜色/计数上赢；caption 由同一 LLM 从同一 latent 解出）合起来指向 **"信息在，但接收方不会用"**，而不是"看不懂"。**"不会用"可训练，"看不懂"要换桥，"没传到"要止损——三种病三种药，必须先分清。**
>
> ⚠️ **同时校正**：NavGPT-2 Table 5 测的是"浅层读出头从隐状态解码离散动作"，**不是**"LLM 用语言决策"。后者在 latent 上**无人测量**，两个邻居是 43（语言+caption，GPT-4）和 21.46（隐状态+浅层头）。**格子是空的，但先验不乐观。**
> 能保留的差别只有三个（写进 paper 时必须逐条说）：他们要的是**离散动作**、我们要的是**语言化取帧请求**（LLM 强项）；⚠️ ~~他们的 latent 是输入层 32 soft token、不是逐层 KV~~ **此条作废**（我们 §5.4 的载体也是输入层伪 token，KV 只是 adapter 读料，见 [03 §0.5](03-eight-risk-papers-explained.md)）；他们从没训过"读 latent 然后发指令"这件事。

### 8.2 ✅ 真空仍在的三份独立证据

1. **穷举扫描**：arXiv 摘要含 "KV cache" AND "visual"，2026-05-01～09-01 共 **39 篇，全部模型内**。没有一例把视觉 KV/hidden state 交给另一个模型。

3. **C2C 自己把两半都列为 future work**：agentic 多轮工具使用 + VLM/VLA cache 融合。**这是"这一步被公认是下一步"的引文。**

### 8.4 白送的评测切片

**BeMyEyes 的流水线会丢弃**那些 "typically because the visual information is too complex or abstract to be effectively conveyed through text-based communication" 的样本。**他们量到了文字瓶颈然后把难题扔了。那批样本就是我们最好的评测切片。**

### 8.5 ❌ 两条不能用的论证

## 11. 一句话风险总结

**这条路的准确率天花板是被封住的**——VideoAgent 自己的消融显示文字通道加宽 10.3 倍只买到 +0.6 分。**所以主张必须是效率（省掉全部 caption 生成 + 不重编码已看过的帧），准确率只需要"不掉"。** 这一条必须在写第一行代码之前想清楚，否则会做出一个"跑得快但没人关心"或"想涨分但涨不动"的东西。

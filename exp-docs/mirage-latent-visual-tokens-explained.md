# Mirage 讲解：让模型"在脑子里想象一张图"到底是怎么做到的

> **缘起**：会话中问到 latent visual reasoning 的三种机制，"视觉流形"那一种没讲清楚——尤其是 Mirage 的数据怎么造、怎么训。本文把它从零讲一遍。
> **对应论文**：[arXiv:2506.17218](https://arxiv.org/abs/2506.17218)，*Machine Mental Imagery: Empower Multimodal Reasoning with Latent Visual Tokens*（CVPR 2026）。
> **读者起点**：知道 Transformer 的 input embedding 是什么、知道 VLM 把图片变成一串 token 塞进序列。**不需要**读过 Coconut / LatentMAS。
>
> **读法**：
> - §1–§3 是概念梯子，**必读**，每节只引入一个新想法
> - §4 是手把手实例，**数字可以自己手算复核**
> - §5 是追问区（预判的坑）
> - §6 术语表，忘了名词回来查
> - §7 进阶：与 IVT-LR / M1 的对比，**跳过不影响理解**

---

## TL;DR

Mirage 让 VLM 在推理中途**吐出几个"latent visual token"**——它们是连续向量，不是词，也不是真的图片。

怎么办到的？分三步：

1. **造范本**：对每道题，用标准答案**画一张辅助图**（helper image），它精确画出了"解这道题时脑子里最该浮现的画面"
2. **把范本变成靶子**：让 VLM 的视觉塔把这张辅助图编码成 patch 特征，再**平均池化**成 $k$ 个向量。这 $k$ 个向量就是训练靶子
3. **训模型把自己的 hidden state 长到靶子上**：用**余弦相似度**损失。训完就把靶子撤掉，让它自由发挥

**一句话记住**：`Mirage = 拿真实图片的池化特征当"临摹范本"，把模型的 hidden state 训到视觉 token 该在的地方，然后撤掉范本。`

---

## 1. 第一级台阶：VLM 的输入序列里，图片和文字是"同一种东西"

先把地基摆平。一个 VLM 处理"图 + 问题"时，输入序列长这样：

```
[文字 token 的 embedding]  [图片 → ViT → projector → 视觉 token 的 embedding]  [文字...]
        ↑ 从词表查表来的                    ↑ 从像素算出来的
        └──────────── 两者都是 d_model 维的向量，拼在同一条序列里 ────────────┘
```

**关键事实**：Transformer 的第一层只做矩阵乘法，**它不检查"你这个向量是不是词表里的点"**。你塞什么它都算。

所以"文字"和"图片"在模型眼里都只是**一串 d_model 维向量**。区别只在于**这些向量是从哪儿来的**：

| | 来源 | 数学形态 |
|---|---|---|
| 文字 token | 从嵌入矩阵 $W_{in}$ 查表 | **离散点集**：$W_{in}$ 有多少行就有多少个可能取值 |
| 视觉 token | ViT 特征过 projector 算出来 | **连续区域**：可以取到无穷多个值 |

**真实数字**（本机 config 实读）：

| 模型 | $W_{in}$ 形状 | ViT hidden → 文本 hidden |
|---|---|---|
| Qwen3-VL-8B | $151{,}936 \times 4096$ | $1152 \times (2{\times}2) = 4608 \rightarrow 4096$ |
| llava-onevision-qwen2-7b | — | $1152 \rightarrow 3584$ |

> **桥句（后文反复回指）**：**模型接受任何 d_model 维向量当输入，但只有落在"它训练时见过的区域"里，算出来才有意义。**

## 2. 第二级台阶："两片区域"是什么意思

上一节说"训练时见过的区域"。这一节把它讲实。

### 2.1 文字那片：15 万个孤立点挤成的锥

$W_{in}$ 是 $151{,}936 \times 4096$，所以文字 token 的全部可能取值就是这 **15 万个点**。

注意 $151{,}936 \gg 4096$，所以这些点**张成的线性子空间就是整个 4096 维空间**（满秩）。

> ⚠️ **所以千万别把"文字区/视觉区"理解成两个正交的线性子空间**——那在数学上直接不成立。

那它们怎么会分开？因为**分布不同，不是子空间不同**。这 15 万个点并不均匀铺满 4096 维球面，它们**挤在一个狭窄的、有强公共方向的锥里**（随便挑两个 token embedding，平均余弦相似度显著大于 0）。

### 2.2 视觉那片：projector 值域

视觉 token 是 $W_p \cdot h_{\text{vit}} + b_p$ 这类映射的输出，取值范围是 **projector 的值域**——一片**连续区域**。

#### 先分清两个词：流形 ≠ 分布

这两个词后文一直用，必须先钉死：

| | 问的是什么 | 比喻 |
|---|---|---|
| **流形**（支撑集） | 点**能**落在哪里 | 一张**纸**——可及的区域 |
| **分布** | 点**实际**怎么堆，哪儿密哪儿疏 | 纸上**墨水的浓淡** |

流形是**集合**，与概率无关，问"可不可行"；分布问"多常见"。
**同一张纸上可以有千差万别的墨迹** ——所以**从流形的性质推不出分布的性质**。

> ⚠️ 顺带纠一个本文早前也用错过的说法：**文字侧严格说既不是流形、也不是连续分布，它是 152k 个离散点**（§2.1）。所以"文字流形"是误用，准确说是"文字 token 的经验分布，支撑集为 152k 个孤立点"。**视觉侧才是连续分布，支撑集为 projector 值域。两边连数学类型都不同。**

#### 两个 backbone 的一处结构差别（只影响"能不能证"，不影响"重不重叠"）

llava-onevision-qwen2-7b 的 projector 是 $1152 \rightarrow 3584$，输入只有 1152 个自由旋钮，所以视觉侧的**流形**秩 $\le 1152$（占 3584 维的 32%）；Qwen3-VL-8B 因为 `spatial_merge_size=2` 先把 2×2 个 patch 特征接起来，是 $4608 \rightarrow 4096$，**不受这个约束**。

> ⚠️ **这条只说明"视觉区是薄片"在 LLaVA-OV 上可以用维度计数证明、在 Qwen3-VL 上只能测。它不预测重叠更多**——秩自由只会把分布推向随机水平（1.0×基线），推不到随机之上。

#### 真正有信息量的是实测（本项目 E4，[Q&A/03](Q&A/03-missing-positive-control-in-card1.md)）

视觉 token 在**文字 top-256 主子空间**里的能量占比：

| | 随机基线 | 文字自谱占比 | **视觉占比** | 视觉/基线 |
|---|---|---|---|---|
| LLaVA-1.5 | 0.0625 | 0.235 (3.8×) | 0.058 | **0.93×** |
| LLaVA-OV | 0.0714 | 0.398 (5.6×) | 0.074 | **1.04×** |
| Qwen3-VL | 0.0625 | 0.187 (3.0×) | 0.108 | **1.7×** |

读法：
- **LLaVA 系 ≈ 1.0×** —— 正是"随机朝向的区域"该有的样子，两个世界**统计独立**
- **Qwen3-VL 1.7×** —— **高于随机就必须有方向上的偏好**，这是 merger 学出来的权重造成的，**与维度计数无关**
- 但 0.108 仍**远低于** Qwen3-VL 文字自身的 0.187 → 判决是"**弱对齐**"，不是"混在一起"

**结论移植纪律**：任何依赖"两个世界"的推论，在 LLaVA 系上更硬、在 Qwen3-VL 上更软，**换 backbone 必须重测**。

### 2.3 最实用的判据：LM head 读不读得懂

$W_{out}$（常与 $W_{in}$ 绑定）定义了"哪些方向能被解码成词"：

- **文字 token**：和 $W_{out}$ 某一行内积很大 → 过 LM head 出来一个尖锐分布
- **视觉 token**：和 $W_{out}$ 每一行内积都很小 → 过 LM head 出来一堆垃圾

> **这就是"两片区域"最好用的操作定义：能不能被 LM head 读成词。**

## 3. 第三级台阶：Mirage 想干什么

现在可以说清 Mirage 的目标了。

人在解题时会"在脑子里浮现一个画面"——不是照片级的，是**简化的示意**（回忆书架轮廓，而不是整个房间）。Mirage 想让 VLM 也这么干。

最直接的想法是**让模型真的生成一张图**（接一个图像解码器）。Mirage 明确否决了这条路，理由是原文说的：图像生成的预训练**会伤害推理能力**（"the heavy image-generation pre-training often hinders the reasoning ability"）。

**Mirage 的选择**：不生成像素，直接吐出**几个落在视觉区的向量**，插进序列继续往下推。

于是问题变成一句话：

> **怎么训练模型，让它自己产生的 hidden state 落到"视觉那片区域"里？**

答案是 §4 的三步。

---

## 4. 手把手实例：一道导航题走完全程

整篇只用这一个例子。

**题目**：给一张地图 + 问题"从起点怎么走到终点？"，标准答案是动作序列 `[右, 右, 上]`。

### 4.1 第一步：造 helper image（辅助图）

**helper image 不是模型画的，是用标准答案程序化造出来的。**

- **导航题**：拿 ground-truth 动作序列 `[右,右,上]`，**在起始地图上把这条路径画成红箭头**
- （另一个例子，拼图题：把候选碎片**拼成一张合成图**，让碎片之间的关系一眼可见）

原文说这张图 "delivers **precisely the visual cues needed** to supervise latent reasoning"。

> **人话**：helper image 就是**"如果模型脑子里能浮现一张图，最该浮现的那张"**。因为是从答案造的，它必然含有解题所需的视觉线索。

### 4.2 第二步：让一个大 VLM 写一条"用到这张图"的推理链

把三样东西一起喂给一个大推理 VLM $M$：**原输入 $\bm{x}$、标准答案 $\bm{y}$、辅助图 $I$**，提示词大意是：

> "写一条通向标准答案的分步推理，并在推理中恰当地用上这张 helper image"

$$\bm{o} = M(\bm{x},\ \bm{y},\ I)$$

因为图嵌在推理链中间，它把链子**切成两段**：

$$\bm{o} = \bm{o}_{\rm pre} \oplus I \oplus \bm{o}_{\rm post}$$

其中 $\oplus$ 是**拼接**（不是加法）。具体到我们这道题：

| 记号 | 内容 |
|---|---|
| $\bm{o}_{\rm pre}$ | "起点在左下角，终点在右上角，我先把可行路径画出来：" |
| $I$ | 🖼️ 画了红箭头的地图 |
| $\bm{o}_{\rm post}$ | "照这条路径，动作序列是 右、右、上。" |

对很多题这么做一遍，得到训练集 $\mathcal{D} = \{(\bm{x}^{(i)}, I^{(i)}, \bm{o}^{(i)}, \bm{y}^{(i)})\}_{i=1}^N$。

### 4.3 第三步（核心）：把图变成"靶子向量"

最直白的做法是**拿这批数据直接训**（让模型学会在推理中间生成 $I$）。原文明确否决：模型**合成 helper image 的能力有限**，会拖累效果。

Mirage 换的思路是：

```
① 辅助图 I ──过 VLM 自己的视觉塔──▶ patch 级特征 {e₁,...,eₙ}
             ⚠️ 注意方向：图 → 特征。projector 在这里是被正常使用的

② {e₁,...,eₙ} ──average pooling──▶ k 个"显著向量" {ê₁,...,êₖ}

③ {ê₁,...,êₖ} 就是【靶子】。训模型：让它在那 k 个位置上
   自己产生的末层 hidden state 去【逼近】这些靶子
```

$$\{\bm{e}_1,\dots,\bm{e}_n\} = f_{\bm\theta}(I), \qquad \{\hat{\bm e}_1,\dots,\hat{\bm e}_k\} = \mathrm{Compress}\big(\{\bm{e}_1,\dots,\bm{e}_n\}\big)$$

> ⭐ **`Compress` 就是简单的平均池化**。原文原话："a lightweight yet **surprisingly effective** strategy"。不是什么复杂模块。

#### 手算：$n=4$ 个 patch 压成 $k=2$ 个靶子

**教学缩参说明**：这里取 $d_{model}=4$ 便于手算，**真实值是 4096（Qwen3-VL）/ 3584（LLaVA-OV）**；patch 数取 $n=4$，真实是几百到几千。

设辅助图过视觉塔后得到 4 个 patch 特征：

$$\bm{e}_1=[2,0,0,0],\quad \bm{e}_2=[0,2,0,0],\quad \bm{e}_3=[0,0,2,0],\quad \bm{e}_4=[0,0,0,2]$$

平均池化（前两个一组、后两个一组）压成 $k=2$：

$$\hat{\bm e}_1 = \frac{\bm{e}_1+\bm{e}_2}{2} = [1,1,0,0], \qquad \hat{\bm e}_2 = \frac{\bm{e}_3+\bm{e}_4}{2} = [0,0,1,1]$$

这两个向量就是**靶子**。

### 4.4 Stage 1：两个损失，把 hidden state 拽过去

模型要同时做三件事：

1. 看着输入 $\bm{x}$ 写出 $\bm{o}_{\rm pre}$
2. 在接下来的 $k$ 个位置上，**产生逼近靶子的 hidden state**
3. 看着前面所有东西（含那 $k$ 个向量）写出 $\bm{o}_{\rm post}$

**视觉损失（这是关键的一个）**：

$$\mathcal{L}_{\rm visual} = \ell_{\cos}\Big(\hat{\bm e}_j,\ g_\theta\big(\bm{o}_{\rm pre},\ \hat{\bm e}_{1:j-1}\big)\Big)$$

其中 $g_\theta(\cdot)$ 是模型在第 $j$ 个位置输出的**末层 hidden state**，$\ell_{\cos}$ 是余弦距离（$1-\cos$）。

原文对这个损失的定性：**"This loss grounds the latent tokens firmly in the visual representation space."**

**文本损失**：

$$\mathcal{L}_{\rm text} = \sum_{i}\ell_{\rm CE}\big(\bm{o}_{{\rm pre},i}\big) + \sum_{i}\ell_{\rm CE}\big(\bm{o}_{{\rm post},i} \mid \bm{x},\ \bm{o}_{\rm pre},\ \{\hat{\bm e}_j\}_1^k\big)$$

> ⚠️ **注意后半段的条件**：$\bm{o}_{\rm post}$ 的交叉熵是**在能看到那 $k$ 个视觉向量的前提下**算的。这逼着模型学会**用**这些 latent token，而不是只负责产生它们然后无视。

#### 手算：视觉损失怎么算出来

假设模型此刻在两个位置产生的末层 hidden state 是：

$$\bm{g}_1 = [3,1,0,0], \qquad \bm{g}_2 = [1,0,2,0]$$

**位置 1**：

$$\hat{\bm e}_1 \cdot \bm{g}_1 = 1{\cdot}3 + 1{\cdot}1 + 0 + 0 = 4, \qquad \|\hat{\bm e}_1\| = \sqrt{2} \approx 1.41421, \qquad \|\bm{g}_1\| = \sqrt{10} \approx 3.16228$$

$$\cos = \frac{4}{1.41421 \times 3.16228} = 0.894427 \quad\Rightarrow\quad \ell_{\cos} = 1 - 0.894427 = \mathbf{0.105573}$$

**位置 2**：

$$\hat{\bm e}_2 \cdot \bm{g}_2 = 0{\cdot}1 + 0{\cdot}0 + 1{\cdot}2 + 1{\cdot}0 = 2, \qquad \|\hat{\bm e}_2\| = \sqrt{2}, \qquad \|\bm{g}_2\| = \sqrt{5} \approx 2.23607$$

$$\cos = \frac{2}{1.41421 \times 2.23607} = 0.632456 \quad\Rightarrow\quad \ell_{\cos} = \mathbf{0.367544}$$

**总视觉损失** $= 0.105573 + 0.367544 = \mathbf{0.473117}$

> **读法**：位置 1 的 $\bm{g}_1$ 方向已经很接近靶子（都在"前两维"那侧），损失小；位置 2 的 $\bm{g}_2$ 有一半能量在第 1 维（靶子那里是 0），方向偏了，损失大 3.5 倍。**梯度会把 $\bm{g}_2$ 往 $[0,0,1,1]$ 那个方向转。**
>
> **自检不变量**：余弦损失只管**方向**不管**长度**。你把 $\bm{g}_1$ 整体乘 100，损失一个字都不会变。这解释了为什么 Mirage 不需要担心 hidden state 模长巨大（本项目实测 $\|h\|=122\sim319$）这件事。

### 4.5 Stage 2：撤掉脚手架（latent relaxation）

把 $\mathcal{L}_{\rm visual}$ **删掉**，只留文本交叉熵。

此时模型自回归产生的 latent 向量不再被强制"像辅助图"，而是**自由漂移到对最终答案最有用的位置**。

> **比喻（全文统一）**：helper image 是**教人骑车时后座那只扶着的手**。Stage 1 扶着，Stage 2 松手——松手之后车子怎么骑最稳，由骑手自己决定，但**不会摔**，因为平衡感已经建立了。

### 4.6 Stage 3 与推理

**Stage 3**：RL 再提一次多模态推理能力。

**推理时**：
- ❌ 没有 helper image
- ❌ 不生成任何像素
- ❌ 不跑额外的视觉编码

模型自己吐出 $k$ 个 latent 向量插进序列，继续往下推。原文的说法是：**"whenever the model chooses to 'think visually', it recasts its hidden states as next tokens"**。

## 5. 追问区（预判的坑）

**Q1：$\oplus$ 是拼接还是相加？**
拼接。$\bm{o} = \bm{o}_{\rm pre} \oplus I \oplus \bm{o}_{\rm post}$ 说的是"前半段文字、然后图、然后后半段文字"排成一列。

**Q2：hidden state 是不是被丢进 projector 了？**
**不是，方向正好相反。** projector 只在**准备靶子**时被使用（图 → 特征）。模型自己产生的 hidden state **从不进 projector**——它是被**余弦损失拽到**靶子附近的。
另外维度上也走不通：Qwen3-VL 的 projector 入口是 4608 维（ViT 侧），而 hidden state 是 4096 维（LLM 侧）。

**Q3：$k$ 个靶子，是把整张图压成 $k$ 个，还是分 $k$ 组各压一个？**
原文只说 `Compress` 用平均池化把 $n$ 个 patch 特征压成 $k$ 个显著向量，**没有指定分组规则**。§4.3 的手算里我按"前一半 / 后一半"分组，是**为了可手算而作的具体化**，不是论文规定。

**Q4：靶子是固定的吗？训练中会变吗？**
$\hat{\bm e}_j$ 由**辅助图过视觉塔**得到。视觉塔参数如果在训，靶子就会跟着漂；论文没有强调冻结。**这是复现时要向作者确认的点。**

**Q5：Stage 1 的第 $j$ 个位置，模型是"看着前 $j-1$ 个真靶子"预测，还是看着自己前面产生的？**
公式里是 $g_\theta(\bm{o}_{\rm pre}, \hat{\bm e}_{1:j-1})$ —— **喂的是真靶子**，即 teacher forcing。推理时没有靶子，只能喂自己产生的，**这里存在训练/推理不一致（exposure bias）**，论文未讨论。

**Q6：为什么不干脆让模型生成真图片？**
原文的理由：图像生成的重预训练**会损害推理能力**；而且图像解码器**产生不了与输入图交错的推理轨迹**。

**Q7：为什么余弦而不是 MSE？**
论文没解释。**我的推断**：MSE 会同时管方向和长度，而 hidden state 的模长量级远大于 embedding（本项目实测 $\|h\|=122\sim319$ vs embedding 均值 1.08）；用余弦可以把"长度"这个自由度让出来，只约束方向。另有已知风险：在 massive activation 存在时 MSE 容易学成常数（见 [research-digest.md](VMAS-latent-collab/research-digest.md) §5.3）。

## 6. 术语表

| 词 | 意思 |
|---|---|
| **helper image（辅助图）** | 用标准答案程序化造出来的示意图，画出"解这道题最该浮现的画面"。**只在训练时存在** |
| **latent visual token** | 模型自己产生的、落在视觉区的连续向量。不是词，不是像素 |
| **靶子 $\hat{\bm e}_j$** | 辅助图过视觉塔再平均池化得到的向量，Stage 1 的回归目标 |
| **Compress** | 就是 average pooling |
| **latent grounding** | Stage 1 的作用：把 latent token"锚定"在视觉表示空间里 |
| **latent relaxation** | Stage 2 的作用：撤掉视觉损失，让 latent token 自由漂移 |
| **流形 / 支撑集** | 点**能**落在哪里的那个集合。与概率无关。⚠️ 文字侧其实是 152k 个**离散点**，叫"文字流形"是误用 |
| **分布** | 点**实际**怎么堆，哪儿密哪儿疏。**从流形推不出分布** |
| **秩受限** | 映射的输入自由度少于输出维度，于是值域只能是高维空间里的一张"低维的纸"。**只约束流形，不约束分布** |
| **能量占比** | 一批向量的二阶矩落在某个子空间里的份额。E4 测的是这个，属于**分布**层面的量 |
| **$\oplus$** | 拼接 |
| **projector / merger** | 把 ViT 特征映射到 LLM 输入维度的模块 |
| **$W_{in}$ / $W_{out}$** | 输入嵌入矩阵 / 输出（LM head）矩阵，常绑定 |

## 7. 进阶：和另外两种机制的对比（跳过不影响理解）

三种"latent reasoning"都在做同一件事——**产生一个向量当下一步的 input embedding**——区别只在**向量从哪来、落在哪片区域**。

| | 向量从哪来 | 落在哪片区域 | 要训练吗 |
|---|---|---|---|
| **M1**（Coconut / Heima / [LatentMAS](../models.py) 的默想步） | 上一步 hidden state 经 $W_a$ 拉回**词表流形** | 文字区 | LatentMAS 版免训练（$W_a \approx I$） |
| **Mirage** | **自己生成**，靠辅助图池化特征做余弦靶子训过去 | **视觉区** | ✅ 三阶段 |
| **IVT-LR**（[arXiv:2510.12603](https://arxiv.org/abs/2510.12603)） | **从输入图的 embedding 里按注意力分数挑 $k$ 个** | **视觉区**（本来就在） | ✅ 四阶段渐进 |

一句话记：**M1 = 心里默念一句话；Mirage = 凭空想象一个画面（但先临摹过范本）；IVT-LR = 取材于现场。**

### 7.1 这为什么解释了本项目的 M1 零载荷

把三样东西并排：

| | 落在哪 | LM head 读得懂吗 | 模型训练时见过吗 |
|---|---|---|---|
| 文字 token embedding | 15 万点的锥里 | ✅ | ✅ 预训练全程 |
| 视觉 token（projector 输出） | projector 值域 | ❌ | ✅ VLM 预训练时天天见 |
| **M1 的默想页向量** | **第三片区域** | ❌（与全词表最大 cos **仅 0.06**，本项目实测） | ❌ **从没见过** |

> **"外星笔迹"的精确含义**：M1 产生的向量**既不在文字点集附近，也没被训练要求落在视觉区**——它落在一片模型**从未被训练去处理的**区域。
>
> 模型能同时处理文字和视觉 token，**不是因为它们几何上兼容，而是因为预训练时两种它都见过**（回指 §1 的桥句）。

M1 的四重复现零载荷结果见 [phase2-results.md](VMAS-latent-collab/phase2-results.md)。

### 7.2 对金页测试的直接含义

本项目 branch 里设计的**甲·金页测试**是「把页槽换成**图像池化嵌入**」——**那正好就是 Mirage Stage 1 的靶子 $\hat{\bm e}_j$ 本身**（辅助图换成输入图而已）。等于是**把靶子直接塞进去、跳过训练**。

所以判读很干净：

| 金页结果 | 含义 | 下一步 |
|---|---|---|
| **金页有载荷** | 模型**读得懂**插在那个位置的视觉向量；M1 失败是因为**写不出来** | ✅ **Mirage 式训练对症**——缺的就是那个余弦损失 |
| **金页无载荷** | 模型**读不懂**插在那个位置的视觉向量（"不识字"） | ❌ Mirage 这条路也救不了，M1 该彻底放弃 |

而且如果金页有载荷，还免费得到一个更强的对照：**IVT-LR 式的"挑真实视觉 token"是免训练的、可以立刻测**；Mirage 式的"生成"要训练。两者一比就知道**"必须是真实视觉 token"还是"生成的也行"**——这是个干净的机制结论，目前没人做过。

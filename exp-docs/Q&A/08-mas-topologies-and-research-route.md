# 多智能体一共有几种拓扑？以及我们该选哪条路走

> **这份文档是什么**：回答两个连在一起的问题——(1) 文本 MAS 那几种固定模式（顺序接力 / 并行投票 / 辩论 / MoA）在多模态里也有吗？(2) 我们到底该做"纯 VLM 之间的 latent 协作"还是"真实场景如 VideoAgent"？
>
> **读者起点**：知道"多个 AI 一起干活"。**MoA 是什么会从零讲。**
>
> **读法**：§1 五种拓扑（含 MoA 讲解）· §2 ⭐ 为什么"agent+工具"是**性质不同**的第五种 · §3 三条路线的取舍与建议 · §4 待补的调研 · §5 术语表。
>
> **状态**：§1–§3 的判断基于已完成的 7 轮调研（97 系统筛查等）。**§1 那张"多模态里有没有"的对照表还在补调研中**（见 §4），表里已填的部分标了证据级别。

---

## TL;DR

1. **文本 MAS 的四种模式，本质上都是"对称"的**——所有 agent 看到同样的东西，传的只是意见。
2. ⭐ **多模态多出第五种：agent + 感知工具。它是"不对称"的**——一端看过像素，另一端没有。**文字边在这里承载的是一次模态转换，而不是一句意见。**
3. **建议走第三条路**：取 VideoAgent 那种不对称场景（真需求所在），但**把两端换成同一个模型**（唯一能免训练站住的地方），**主张写效率而不是准确率**。

## §1 五种拓扑

### 1.1 前四种（文本 MAS 的经典模式）

| # | 模式 | 一句话 | 每个 agent 在干什么 | 有没有"说服" |
|---|---|---|---|---|
| **1** | **顺序接力** | 流水线，各司其职 | **分工不同**（planner→critic→refiner→judger） | 无 |
| **2** | **并行投票** | 各答各的，最后数票 | 都答同一题，**互相看不见** | 无 |
| **3** | **辩论** | 吵一架再定 | 都答同一题，**看得到别人的、要反驳** | ⭐ 有 |
| **4** | **MoA** | 分层重写 | 都答同一题，**看得到别人的、但只管写更好的一版** | 无 |

**2 和 3 的区别**：投票时 agent 之间**没有可见性**；辩论有。
**3 和 4 的区别**：辩论要**反驳**；MoA 只**重写**。
**4 和 2 的区别**：MoA 有**多层**、且每层每个人都读过上一层所有人的答案；投票只有一轮。

### 1.2 MoA 详解（你问的那个）

**Mixture-of-Agents**，Wang et al. 2024，[togethercomputer/MoA](https://github.com/togethercomputer/MoA)。

```
第 1 层：  A₁  A₂  A₃  A₄  A₅      ← 5 个"提议者"各自独立答一遍
              ↓ 把全部 5 份答案作为上下文，喂给下一层
第 2 层：  B₁  B₂  B₃  B₄  B₅      ← 每人读完 5 份，各自写一份"更好的答案"
              ↓
第 3 层：  ...                      ← 重复 L 层
              ↓
最后：      Aggregator（汇总者）     ← 把最后一层的 N 份合成最终答案
```

**通俗版**：五个人各写一稿 → 每人读完所有人的稿子、各自重写一版 → 重复几轮 → 最后一个人把大家的合并。**没人反驳谁，每个人只管把自己那版写得更好。**

**为什么它重要**——【论文】Wunderlich 等（[2605.01566](https://arxiv.org/abs/2605.01566)）是**唯一把这几种画在同一条算力轴上**的工作，MMLU-Pro / Llama-3.1-70B / 1000 题：

```
CoT 64.3  →  并行投票 68.7（~10 样本饱和）  →  辩论 70.0（~4 agent 饱和）  →  MoA 71.4（20× 算力仍在上升）

等算力下： MoA 比并行投票高 +2.7，比辩论高 +1.3
⭐ 而且它的 MoA 是「同一个 backbone 当提议者」——不是靠模型异质性
```

> ⭐ **这是我们整个调研里唯一一个"未训练 + 同 backbone + 等算力还能赢"的正面例子。** 参见 [Q&A/05 §5.1](05-credible-mas-screening-and-graft-plan.md) 的三种曲线形状——MoA 属于"升→饱和"那一类，不像辩论那样会掉回单模型以下。

另有 **Self-MoA** 一路批评，说"单模型 MoA 比混模型 MoA 还好"，与上面同向。

### 1.3 多模态里有没有？（部分已知，部分待补）

| 模式 | 多模态实例 | 证据级别 |
|---|---|---|
| **1 顺序接力** | ✅ **很多**：L²-VMAS 的 VMAS 基线（沿拓扑链接力）· MDocAgent（5 角色）· RadAgents · MAPS（7 agent，4 段求解链）· Insight-V（推理→总结）· VideoHV-Agent（Thinker→Judge→Verifier→Answer）· PixelCraft | 【核实】 |
| **2 并行投票** | ✅ **有**：**ViF 公开代码就是这个**（N 个角色 worker 并行跑，置信度加权多数投票）· LVAgent（并行后讨论）· A4VL（线程并行 + 交叉评审）· InsightSee（描述 agent + 两个并行推理 agent + 决策投票）· 退化情形 = VLM 上的 self-consistency / VisualPRM 的 Best-of-N | 【核实】 |
| **3 辩论** | ✅ **有**：BDoG（在实体关系图上辩论）· AlignVQA（VQA 校准）· DART 的两条辩论基线 | 【核实】 |
| **4 MoA** | ⚠️ **疑似空白** —— 目前只找到形状最接近的 **Visual Para-Thinker++**（Main 分解 → Workers 并行、上下文隔离 → Summary 汇总完整轨迹），但**它没有"多层"**，且**无公开代码** | 【推断，调研中】 |
| **5 agent+工具** | ✅ **最多**，且**效果最好**：OmniAgent · VideoAgent×2 · ViperGPT · VisProg · Chameleon · MM-ReAct · Visual Sketchpad · DeepEyes · PixelCraft | 【核实】 |

> **如果 MoA 那格确实是空的，值得知道原因**：MoA 的成本是 **L 层 × N 提议者**次前向，而在 VLM 上**每一次都要重新编码图像**。文本里这只是多几百个 token，视觉里是每次多几千个 token。**这个成本结构可能就是它没被搬到多模态的原因** —— 而这恰恰是 KV 复用能解决的问题。（待 §4 的调研确认。）

## §2 ⭐ 为什么第五种性质不同

前四种有个共同点：**所有节点看到的东西是一样的**。它们之间传的只是"意见"。

```
前四种（对称）：      ○ ←文字→ ○         两端都看过同样的东西
                     "我觉得答案是 A"      文字丢的是「意见的措辞」

第五种（不对称）：    👁 ←文字→ 🧠         一端看过像素，另一端没有
                     "图里有个人在洗碗"     文字丢的是「它看到的一切」
```

> **桥句**：**前四种模式里，文字边是对称的；agent+工具里，文字边是不对称的——它承载的是一次模态转换。**

**具体到系统**：
- **OmniAgent**：8 个"工具"全是大模型（Gemini 定位音频事件、qwen3-vl-flash 答视频问题…），但**大脑 o3 一个像素都没见过**
- **VideoAgent**：大脑是纯文本 GPT-4，整段视频只以 caption 字符串存在于它的上下文里，而且 **caption 是问题无关、离线预算好的**

### 2.1 这个区分正在被我们自己的实验测量

**我们的 C1 实验，测的恰好就是这两类的差距**：

| 我们的臂 | 结构上属于 |
|---|---|
| `text`（**只有 Planner 看图**） | **第五种：agent+工具型**（不对称，下游全盲） |
| `textsighted`（**4 个都看图**） | **前四种：TextMAS 型**（对称） |

所以 A4 那个数出来，我们同时得到了"这两类设定差多少"。**这不是巧合，实验设计本来就切在这条缝上。**

### ⭐ 2026-08-04 结果（4 配置全量 n=800/798，官方 exact match）

| 配置 | Single | text（下游盲） | **textsighted（都看图）** | Δ sighted−Single (p) |
|---|---|---|---|---|
| LLaVA-OV / GQA | 59.4 | 43.0 | **57.6** | −1.8 (0.19 n.s.) |
| LLaVA-OV / MMStar | 53.9 | 38.7 | **54.8** | +0.9 (0.55 n.s.) |
| Qwen3-VL / GQA | 63.2 | 38.2 | **45.6** | **−17.6 (8.3e-24)** |
| **Qwen3-VL / MMStar**（预注册基准格） | 61.8 | 49.9 | **62.7** | +0.9 (0.66 n.s.) |

（完整表含 latent 臂见 [phase2-results.md](../VMAS-latent-collab/phase2-results.md) `C1-rev` 节。）

**三条判读**：

1. **"给下游看图"确实把大部分损失捞了回来**（基准格 sighted ≈ Single）→ 第五种模式（不对称、下游盲）比前四种模式**结构性地丢分**，这个差就是"模态转换税"。
2. ⚠️ **但代价换向**：Qwen3-VL/GQA 上 sighted 反而 **−17.6**（真实掉分，非判分伪影）→ **让每个 agent 都看图，在简单感知题上会把对的答案聊反**。所以两类模式不是"一个好一个坏"，而是**各有一个失效区**：不对称模式丢信息，对称模式多轮讨论会自我污染。
3. **latent 通道的优势也随之塌了**：`Latent(m=0) − textsighted` = **+1.2 / −4.7 / +9.9 / −0.5**（对比 `− text` 的 +11~17）→ **latent 的卖点必须从"准确率"改成"效率"**（省 N−1 次视觉编码 + 零中间 token）。

**顺带一条自责的收回**：拓扑调研核实 **8 个角色分工接力系统里 7 个都是"头部 caption 一次、之后盲推"**（MAPS 源码里 `Aligner/Scholar/Solver.call_LLM` 签名根本没有 image 参数；只有 Insight-V 全程多模态）→ **我们的 `text` 臂复现的正是领域主流设计**，不是"人为削弱的 baseline"。

## §3 三条路线的取舍

### 路线甲：纯 VLM 之间 latent 协作 + 采用某种 TextMAS 模式

❌ **不建议。** 这是 [Q&A/06 §8](06-latent-collab-design-space-and-brain-tool-edge.md) 排序里的 **#12，判定 not worth doing**：

> "饱和且已被争议：18+ 方法、两个 spotlight、一篇综述、一个安全子领域已占满。**边际方法无处立足**"

而且我们自己的 C1 已经测出这条路在对称设定下 ≈ 0（§2.1：sighted 臂 −1.8/+0.9/−17.6/+0.9，全部 n.s. 或为负；角色不带来新信息源，MAS 本就不该无中生有）。

### 路线乙：照搬 VideoAgent 场景

⚠️ **格子没被占，但两个硬伤。**

**硬伤 1——天花板已被实测封住**（[Q&A/06 §8.5](06-latent-collab-design-space-and-brain-tool-edge.md)，VideoAgent 自己的消融）：

```
文字通道加宽 10.3 倍（7.2 词 → 74.2 词/caption）  →  只买到 +0.6 分
接收方从 GPT-3.5 换成 GPT-4                       →  +11.4 分
                                                     ↑ 接收方的推理力比通道重要约 19 倍
```

**硬伤 2——跨模型漂移**：原版 VideoAgent 的大脑是 GPT-4、captioner 是 LaViLa，**两个不同家族**。[Q&A/06 §6.1](06-latent-collab-design-space-and-brain-tool-edge.md) 实测的漂移（rope_theta 5e6 vs 1e6、k/v 投影漂移 15–27%、**第 0 层 V-cache 误差已 31.9%**）会直接把免训练路线打死。

### ⭐ 路线丙（建议）：保留不对称性，但让两端是同一个模型

```
VideoAgent 式的循环，但 viewer 和 reasoner 是同一个 Qwen3-VL-8B：

  第 k 轮：模型看第 {f₁..fₘ} 帧  →  产生 KV
                                    ↓ 保留、累积（不生成 caption）
  第 k+1 轮：模型读累积 KV + 决定下一批看哪几帧  →  再看 → 再累积
                                    ↓
  终轮：出答案
```

**逐条对齐证据**：

| 要素 | 依据 |
|---|---|
| **不对称性保留了** | 第 k+1 轮要用到第 k 轮看过、但已不在上下文里的帧 → 文字边**真实存在**，不是我们造的 |
| **目标人群存在且是多数** | [§8.5](06-latent-collab-design-space-and-brain-tool-edge.md) 实测：VideoAgent **72.2% 的题至少重调一次**感知工具，**73.3% 的自评说"当前报告不够用"** |
| ⭐ **同一个模型 → 漂移问题消失** | §6.1 那些 15–27% 漂移只在**不同模型间**出现 |
| ⭐ **落进最大的空格** | [§4.2 空格 1](06-latent-collab-design-space-and-brain-tool-edge.md)：**没有任何论文传过 VLM 的逐层 KV（含图像 token）**，而图像 KV 正是算力所在（一张 1080p 图 279 MiB） |
| **不是 #12** | 这不是"角色型 MAS 里的 peer→peer"，是**感知回路里的跨轮状态传递** |
| **主张改成效率** | 原版**每帧每轮都要生成 caption**；改版**一个中间 token 都不生成**，且不重编码已看过的帧。VideoAgent 平均只用 8.4 帧 → **要么同帧数涨分，要么同分数再砍帧，两种赢法** |

**必须先知道的风险**：
- ⚠️ 准确率的天花板仍被那个 +0.6 分压着 → **主张必须是效率，不能是准确率**
- ⚠️ **原生 crop/zoom 一族是结构性威胁**（DeepEyes / Pixel Reasoner / Qwen3-VL 原生工具，压缩比 1:1、根本没有文字边）："你控制 backbone 的话，直接把像素还回去让模型重新编码就行"。我们的反驳只能是"重新编码要付 N 次视觉 prefill，KV 不用"——**这是可量化的效率论证，但也仅此而已**

### 3.1 落地上的好消息

这条路和已有工作高度复用：

- **现成冒烟台**：[Q&A/05 §7.3](05-credible-mas-screening-and-graft-plan.md) 的 graft 排名里，**VideoChat-A1**（[SpXace/VideoChat-A1](https://github.com/SpXace/VideoChat-A1)）是**唯一零改动全过 P1/P2/P3 的仓库**——单模型、轮次串行、纯 HF、摸得到 `past_key_values`
- **视频位置编码几乎免费**：Qwen3-VL 把视频当"一串独立单帧 + 文字时间戳"（`modeling_qwen3_vl.py:923` 原话："use **timestamps** rather than absolute time position ids"），现有图像 tracker 可近乎直接泛化
- **可借的零件**：PixelCraft 的"中间图落盘 + path→描述索引"是现成的跨轮状态管理方案（见 [07 §5](07-orchestra-o1-and-pixelcraft-explained.md)）

## §5 术语表

| 词 | 一句话 |
|---|---|
| **顺序接力** | 多个角色排成流水线，各司其职 |
| **并行投票** | N 个 agent 独立答同一题，数票；agent 之间看不见彼此 |
| **辩论** | N 个 agent 看得到彼此的答案，互相反驳、多轮修正 |
| **MoA** | 分层重写：每层每人读完上层所有答案，各写更好的一版；最后一个汇总者合并 |
| **Self-consistency (SC@k)** | 同一个模型采样 k 次投票 = 并行投票的退化情形（同模型、无角色） |
| **agent + 工具** | 一个决策者调用若干"设备"；设备可以本身是大模型 |
| **对称 / 不对称边** | 两端看到的东西一样 / 不一样。不对称边上，文字承载的是一次模态转换 |
| **KV cache** | 模型算过的中间状态缓存，详见 [06 §1](06-latent-collab-design-space-and-brain-tool-edge.md) |
| **prefill** | 读输入的阶段（视觉编码发生在这里，是多模态的大头） |

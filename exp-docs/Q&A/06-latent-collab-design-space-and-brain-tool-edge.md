## TL;DR（三句话）

1. **"传 latent" 不是一件事，是五件事。** 真正的分水岭不是"传什么"，而是**接收方拿到之后怎么用**——LatentMAS 和 C2C 在这一点上根本不是同类。
2. **最大的空白：没有任何论文传过 VLM 的逐层 KV（含图像 token）。** 而图像 token 的 KV 正是算力所在。
3. ⚠️ **"把 AI 之间的文字交接换成 latent 交接"这个想法，我们做了体检，三处塌了。** 最重要的一课是：**压缩比测的是带宽，不是损失。**

## §1 地基：模型算完一段话，脑子里剩下什么？

### 1.1 一个贯穿全文的比喻：交接班

整篇文档我用**交接班**打比方，中途不换：

| 比喻 | 技术概念 |
|---|---|
| 一个人上完班 | 模型处理完一段输入 |
| **他脑子里的工作记忆** | **KV cache** |
| **写张便条交给下一班** | 文字通道 |
| **把工作记忆整个搬给下一班** | latent / KV 通道 |
| 下一班怎么用这份记忆 | §3 的五种消费方式 |

### 1.2 KV cache 是什么

大模型吐字是一个字一个字来的。吐第 10 个字的时候，它需要"回头看"前面 9 个字。

**如果每吐一个字都把前面全部重算一遍，代价是平方级的。** 所以模型把每个字算过的中间结果存下来，下次直接查——这份存下来的东西就叫 **KV cache**。

**为什么叫 K 和 V**：注意力机制里，每个 token 会算出三个向量——Query（我要找什么）、Key（我是什么，供别人找）、Value（找到我之后能拿走什么内容）。Q 每步都要重算，但 **K 和 V 只跟这个 token 自己有关，算一次就能一直用**。所以缓存的是 K 和 V。

### 1.3 手算一遍（教学缩参，真实值随后给）

假设一个玩具模型：**2 层**，每层每个 token 各产生 **1 个 K 向量 + 1 个 V 向量**，向量维度 **4**。

输入 3 个 token：`猫`、`坐`、`垫`。

| 层 | token | K 向量（4 维） | V 向量（4 维） |
|---|---|---|---|
| 第 1 层 | 猫 | k₁₁ | v₁₁ |
| 第 1 层 | 坐 | k₁₂ | v₁₂ |
| 第 1 层 | 垫 | k₁₃ | v₁₃ |
| 第 2 层 | 猫 | k₂₁ | v₂₁ |
| 第 2 层 | 坐 | k₂₂ | v₂₂ |
| 第 2 层 | 垫 | k₂₃ | v₂₃ |

**KV cache 的总量 = 层数 × token 数 × 2（K 和 V）= 2 × 3 × 2 = 12 个向量。**

> **桥句（记住这句，后文反复用）**：
> **KV cache 是一张"层 × token"的二维表格，每格装着 K 和 V 两个向量。**
> "传 latent" 说白了，就是**把这张表格的一部分交给另一个模型**。

### 1.4 ⚠️ 真实值有多大

上面为了画表把参数缩小了。**真实的 Qwen3-VL-8B**：

```
36 层 × 8 个 KV 头 × 128 维 × 2（K 和 V） = 73,728 个数 / 每个 token
按 bf16（每数 2 字节）算：73,728 × 2 = 147,456 字节 = 144 KiB / 每个 token
```

一张 1080p 的图在 Qwen3-VL 里约占 **1,980 个 token**，所以**光这一张图的 KV 就是 1,980 × 144 KiB ≈ 279 MiB**。

**记住这个量级**——§7 会用到。

## §2 "传 latent" 到底传什么？

回到交接班：你要把工作记忆交给下一班，可以交多少？

| 传什么 | 白话 | 代表 |
|---|---|---|
| (a) **整张表** | 所有层、所有 token 的 K 和 V | LatentMAS |
| (b) **表的某几行**（层的子集） | 只交前 10% 的层 | LACO、KVComm |
| (c) **表的某几列**（token 的子集） | 只交关键那几个 token | KVComm |
| (d) **一小段"摘要向量"** | 不交原表，交 m 个学出来的浓缩向量 | MACF（K=32 个）、L²-VMAS（L=8 个） |
| (e) **层的输入激活**（不是 K/V 本身） | 交上游一层的输入 | 部分方法 |
| (f) **量化/低秩的替身** | 压缩过的近似版 | Q-KVComm |

**但这只是第一条轴。真正的分水岭在下一节。**

## §3 ⭐ 核心：接收方拿到之后怎么用——五种方式，不可互换

这一节回答你最初的问题：**"C2C 是 KV 直接叠加，LatentMAS 是把上层 KV 当 prefix，这两个到底什么关系？"**

答案：**它们是五种消费方式里的两种，而且是最不一样的两种。**

### 3.1 五种方式

| # | 方式 | 交接班比喻 | 序列长度 | 代表 |
|---|---|---|---|---|
| **(i)** | **前缀拼接** | **把我的笔记本放在你笔记本前面**，你翻的时候能翻到 | **变长**（N → N+M） | **LatentMAS**、LACO、KVComm、Agent Primitives |
| **(ii)** | **加性 / 原位融合** | **直接在你自己的笔记上改字** | **不变** | **C2C**、LRAgent |
| **(iii)** | 交叉注意到外部记忆 | 我的笔记放在旁边书架上，你需要时抬头看一眼 | 不变 | **KV 族里是空的** |
| **(iv)** | 当输入重新走一遍 | 把我的笔记**念给你听**，你从头重新理解一遍 | — | Vision Wormhole；LatentMAS 的**agent 内部**默想循环 |
| **(v)** | 恢复 + 稀疏重算 | 把我的笔记装进你的笔记本对应页，**再挑几页重写**修正 | — | CacheBlend、DroidSpeak、KVCOMM、RelayCaching |

### 3.2 (i) 和 (ii) 到底差在哪

这是最容易混的一对，值得单独讲：

**(i) 前缀拼接（LatentMAS）**
```
接收方原来的 KV 表:        [自己的 token 1..N]
拼接之后:        [发送方的 M 个] + [自己的 token 1..N]
                  ↑ 新增的位置
```
接收方的注意力现在能看到发送方那 M 个位置。**但也意味着：发送方的内容要和接收方自己的 token 在同一个 softmax 里抢注意力权重。**

**(ii) 加性融合（C2C）**
```
接收方原来的 KV 表:  [自己的 token 1..N]
融合之后:            [自己的 token 1..N]   ← 位置数不变
                      每一格的值被改写成:
                      新K = 门控(自己的K, 投影(发送方的K))
```
**序列不加长，接收方自己的表示被直接改写。**

| | (i) 前缀拼接 | (ii) 加性融合 |
|---|---|---|
| 序列变长吗 | ✅ 变长 | ❌ 不变 |
| 接收方自己的状态被改吗 | ❌ 不改，只是多了可看的东西 | ✅ **被改写** |
| 要训练吗 | ❌ 可以免训练 | ✅ **必须训**（要学那个投影和门控） |
| 要求同一个模型吗 | ✅ 通常要求架构相同 | 可以跨模型（因为有学出来的投影） |

### 3.3 一条经验规律

> **前缀拼接主导"求精度"的方法；恢复+重算主导"求延迟"的方法；加性融合基本上只有 C2C 一家。**

这对应第六条轴——**目标**：

- **求精度**（C2C、LatentMAS、Agent Primitives）：发送方贡献的是接收方**没有的语义**
- **求延迟**（DroidSpeak、KVCOMM、RelayCaching）：发送方贡献的是接收方**本来要重算的计算**

### 4.3 ⭐ 空格 8 展开：唯一那篇因果审计说了什么

**因果审计**（[2607.26773](https://arxiv.org/abs/2607.26773)）问了一个别人不问的问题：**"接收方真的用了发送方的消息吗，还是消息只是个触发器？"**

它的做法：把发送方的消息**换成另一道题的消息**，看分数掉不掉。

结果（GSM8K / Qwen3-4B）：
```
latent 通信的总效应:        −1.00 分
拆开看:
  「消息存在」的效应:       −6.17 分
  「消息内容对不对」的效应:  +5.17 分
```
**总分可以由两个方向相反的分量合成。只看总分会得出完全错误的结论。**

更狠的一条：**发送方的消息，在等算力下比"接收方自己生成的消息"还差 2.00 分。**

> ⭐ **对本项目的直接背书**：审计指出全族缺两个对照——**换成别的样本的消息**（我们的 **Xshuf 臂**）和**接收方自己生成的消息**（我们的 **U 臂**）。**没有一篇主方法论文做过，我们两个都有。**

⚠️ 另一条必须刻进纪律的警告：另一份分析发现，**+10.00 分的 latent 增益里，有 +8.13 分在"消息来自另一个样本"时仍然存在**——**绝大部分 latent 增益不是内容特异的**。任何 latent 正结果不做 shuffle 对照就没有意义。

## §5 一个很诱人的想法：让"眼睛"直接把脑子交给"大脑"

### 5.1 想法本身

现在的多模态 agent 系统长这样：

```
   [ 视频/图片 ]
        ↓
  ┌──────────────┐
  │ 工具 = 视觉模型│  ← 它真的看了像素
  └──────────────┘
        ↓  写一句话（caption / 答案）
  ┌──────────────┐
  │ 大脑 = 文本模型│  ← 它一个像素都没看到
  └──────────────┘
        ↓
      最终答案
```

**"眼睛"看到的一切，都被压成一句话才交给"大脑"。** 想法很自然：**把这条文字线换成 latent 线**，让大脑直接拿到眼睛的工作记忆。

### 5.2 为什么听起来对

- 这条边在真实系统里**到处都是**（VideoAgent、OmniAgent、BeMyEyes、Cola、IdealGPT……）
- 而且这些系统**是有效的**（工具增强的 agent 能涨 10–20 分），不像角色型多智能体那样效果≈0
- 压缩比看起来惊人（后面会讲这是个陷阱）

## §6 体检：三处塌了

### 6.1 塌点一：同一家族的免训练交接，大概率死在起点

**为什么会觉得可行**：Qwen3-VL-8B 的"语言塔"（去掉视觉部分剩下的文本模型）和 Qwen3-8B **形状完全一致**：

```
hidden 4096 · 36 层 · 32 个 Q 头 · 8 个 KV 头 · head_dim 128 · vocab 151936
```

形状一致 = KV cache 可以**直接装进去**，不需要任何转换器。

**但【实测，agent 在本机跑的探针】说不行**：

| 检查项 | 结果 |
|---|---|
| ✅ **M-RoPE vs 1D RoPE** | **是个伪问题**。数值验证：多模态位置编码对**纯文字 token 精确退化成普通 1D 位置编码**（`max abs diff = 0.0`）。比我原先估计的好 |
| ❌ **`rope_theta` 不一样** | Qwen3-VL 是 **5,000,000**，Qwen3-8B 是 **1,000,000**。**位置一超过约 64 就退相关**（平均 cos 0.713） |
| ❌ **权重漂移** | k/v 投影矩阵的相对漂移约 **15–27%**，是 Qwen3 自己后训练漂移（6–10%）的 **2.3–2.7 倍**，且**随层数加深单调增大** |
| ❌ **端到端误差** | 真实 24-token 提示过**第 0 层**：V-cache 相对误差已 **31.9%**（cos 0.948）。**这是最浅的层，还没开始累积** |
| ❌ **chat 控制符最糟** | `<\|im_start\|>` / `<\|im_end\|>` 是**全模型漂移最大的向量**（相对误差 54% / 57%，而普通文字 token 只有 16–20%）→ **模板化提示的结构支架处误差最大** |

> **判决**：这个模型对上的**朴素**免训练交接不可行——漂移已远超别的工作测到"朴素复用掉 50% 以上准确率"的区间。
> **幸存的窄版本**：**校准式**交接——只传**文字 token** 的 KV，且必须 (a) 把 key 按 5e6 反旋、再按 1e6 对接收方的位置重旋；(b) 只传**没有视觉贡献**的位置。

**跨家族要花多少钱**【调研】：Vision Wormhole 每个模型 ~41M 的编解码器、400 步、**3–6 GPU·时**；Latent Cache Flow 19.4M 的适配器、300 步、**单 A100 约 4.5 小时**；C2C 每一对模型 477.8M 参数、**O(N²)** 对数。

### 6.2 塌点二：这条边到底值多少分？唯一的直接测量分不出与零的差别

**TAMA**（[2510.00161](https://arxiv.org/abs/2510.00161) Table 5）跑的正是这个消融：**同一个 agent、同一套工具、同一个评测集，唯一差别是感知工具交回「图像本身」还是「同一个模型给这张图写的 caption」**：

| 模型 | 交 caption | 交图像 | 差 |
|---|---|---|---|
| GPT-5 mini | 59.0 | 63.7 | +4.7 |
| Gemini 2.5 Flash | 48.2 | 52.4 | +4.2 |
| Qwen2.5-VL 32B | 39.0 | 42.1 | +3.1 |
| MiMo-VL 7B | 50.9 | 49.6 | **−1.3** |

自己算一遍：
```
均值 = (4.7 + 4.2 + 3.1 − 1.3) / 4 = 10.7 / 4 = +2.68
标准差 ≈ 2.73，标准误 = 2.73 / √4 = 1.37
t = 2.68 / 1.37 = 1.96，自由度 3 → p ≈ 0.145
```
**分不出与零的差别。**

而且有两条更要命的：

1. **这点增益是靠"直接把图传过去"拿到的**——而**每个视觉大脑本来就支持这么做**，根本不需要 latent 通道。
2. **在任何模态里，都不存在"文字边换成 latent 边能额外涨多少"的测量。**

### 6.3 塌点三：格子是空的，但"方向"已经被占了

**确实空着的**：视觉模型发送 → 纯文本模型接收 → 走 KV/hidden。没有任何一篇同时满足四条：(a) 发送方真的会看、(b) 传 latent 不传文字、(c) 接收方是独立选定的文本推理模型、(d) 在带工具调用的循环里。

**但"方向"被占了四层**：

| 谁 | 占了什么 |
|---|---|
| ⚠️ **L²-VMAS** | **逐字claim了这个 framing**："text-centric communication is an information bottleneck" + "**decouple perception and thinking**"，而且**评测就在 LLaVA-OV-1.5-8B 和 Qwen3-VL-8B 上——正是本项目的现役模型**。差别只是它的思考端是视觉模型不是纯文本模型——**这是替换，不是方向** |
| ⚠️ **Vision Wormhole** | 占了"视觉模型 latent 接口"这个端口，并**明确拒绝了它的 KV 变体** |
| 先例链 | 感知 → 冻结推理器的 latent 接口可上溯 **Frozen / LiMBeR / BLIP-2** |
| ⚠️⚠️ **最大被抢风险：Latent Cache Flow**（[2605.22863](https://arxiv.org/abs/2605.22863)） | 专治"两个模型上下文不同"的 KV 翻译，适配器只有 13MB（C2C 的 4%）。它论文里那句 "unsuitable for agent communication, **where the LLMs have differing context**" 就是这个场景。**谁把它的发送方换成一个视觉模型，这 idea 就没了** |

**必须正面推翻的靶子：SeeingEye**（[2510.25092](https://arxiv.org/abs/2510.25092)）——最接近的循环，且**明确站在对立面**："allows the text-only agent to operate in its native domain, processing rich, structured textual information **rather than latent visual features**"。

## §7 ⭐ 最重要的一课：压缩比测的是错的东西

### 7.1 先看那些吓人的数字

【实测，读源码 + 算】OmniAgent，180 秒 640×360 的视频，"编码器内部 token 数 : 交回去的文字 token 数"：

| 工具 | 比值 |
|---|---|
| 整段视频问答（fps=2） | 53,820 : ~150 = **~359 倍** |
| 整段视频问答（fps=5，Gemini 路径） | 232,200 : ~150 = **~1548 倍** |
| 5 秒片段问答 | 3,738 : ~150 = **~25 倍** |
| 音频问答 | **~38–48 倍** |
| **语音转写（ASR）** | 2,250 : ~600 = **~3.8 倍** ← **唯一接近无损的工具** |

> 最后一行值得停一下：**转写是双射（一段语音 ↔ 一段文字，一一对应），不是摘要**。所以它几乎不丢东西。**这个反差本身就提示：丢的不是"字数"，是"摘要这个动作"。**

### 7.2 ⭐ 但压缩比是错的度量

真正决定 latent 通道能不能赚钱的量，是这个：

$$I(\text{答案};\ \text{发送方内部状态}\ \mid\ \text{问题},\ \text{文字报告})$$

**白话**：在**已经知道问题、也已经读了那份文字报告**的前提下，发送方脑子里**还剩多少**跟答案有关、但没写进报告的信息。

**对一个"知道问题才动手"的工具，这个量通常很小**——因为它已经按问题把该提取的提取了。

**两条硬支撑**：
- **OmniAgent 完全由文字边构成，却比"零文字边"的端到端全模态模型高 6.7–20.7 分**
- **VideoAgent 靠的仅仅是"在文字线上做问题条件化"，就比 LLoVi 高 11 分**

> **桥句**：
> **压缩比衡量的是带宽，不是失真。便条比脑子小一千倍，不等于便条漏掉了有用的东西——因为便条是照着问题写的。**

### 7.3 ⭐⭐ 一个直接把天花板封死的实验（别人做的）

VideoAgent 论文自己的消融，**直接给出了"把文字通道加宽能买到多少"的经验上界**：

| 换成什么 captioner | 每条 caption 多长 | 分数 |
|---|---|---|
| LaViLa | **7.2 词** | **60.2%** |
| CogAgent | **74.2 词** | **60.8%** |

自己算：
```
通道宽度倍数：74.2 ÷ 7.2 = 10.3 倍
换来的分数：  60.8 − 60.2 = +0.6 分
```

**文字通道加宽 10.3 倍，只买到 0.6 分。**

同一篇里另外两个数，把这件事钉死：

```
感知量：  8.4 帧精选 60.2%  >  180 帧均匀采样 59.6%   ← 更多感知反而有害
接收方：  GPT-3.5 48.8 → GPT-4 60.2 = +11.4 分
         11.4 ÷ 0.6 ≈ 19 倍                        ← 接收方的推理力比通道重要 19 倍
```

> **如果 §7.2 那个信息量在这里很大，CogAgent 长 10 倍的 caption 本该找回大部分。它只找回了 0.6 分。**

#### (1) 判死条件"多调用 regime 存在吗"——**通过，且是多数情形**

| 指标 | 实测 |
|---|---|
| **至少重调用一次感知工具** | **361/500 = 72.2%** |
| 打到硬上限 2 次 | 260/500 = 52.0% |
| **自评判定"当前文字报告不够用"** | **621/847 = 73.3%** |

#### (3) 15 条边里最值得注意的四条

| 边 | 压缩比 | 发现 |
|---|---|---|
| ⭐ **IdealGPT**：BLIP-2 → 盲推理器 | 对 ViT 原始 token 是 **26:1**；**但对 BLIP-2 自己的内部 latent 只有 32:10 = 3.2:1** | **BLIP-2 的 Q-Former 已经把 257 个视觉 token 压成 32 个学出来的向量——那本身就是一条内部 latent 通道，而 IdealGPT 把它扔了**，重新序列化成 ≤10 个文字 token（`max_length=10`、`length_penalty=-1` **显式推向最短字符串**）。**3.2:1 是诚实的 headroom**——宽度窄，但性质完全不同（连续、未 argmax）。**全清单里工程量最小的 drop-in 格子** |
| ⚠️ **原生 crop/zoom 返回像素**（DeepEyes / Pixel Reasoner / Qwen3-VL 原生工具） | **1:1，根本没有文字瓶颈** | crop 通过同一个编码器以视觉 token 重新进入。**"如果你控制 backbone，你不需要 latent 通道，直接把像素还回去让模型重新编码就行。"** → **这一族基本让单模型 agent 的整条 latent 纲领失去意义；latent 只在两端不能共享编码器时才有价值** |
| ⚠️ **ViperGPT / VisProg** | 未定义 | **它们几乎不含"感知→模型"的文字边**：值以**带类型的 Python 对象**流动（bbox 就是 bbox，零序列化损失），且推理模型**发出一个程序就退出**，循环里根本没有模型 |
| **SeeingEye 的中间表示** | **1.3:1** | 全清单**最宽的感知文字线，几乎不压缩**。所以它反对 latent 的立场是有底气的——**它已经把文字通道加宽到接近无损了** |

#### (4) 选 host 系统时必看：人群是**双峰**的

- **零重调用（结构上不可能）**：Cola（输出全部离线预算）· MDocAgent（直线函数无循环）· Chameleon（离线 OCR）· ViperGPT/VisProg（发一个程序就退出）· M3DocRAG

→ **左边那一列连 regime 都不存在，选 host 只能从右边挑。**

## §9 两个极便宜的判死实验

### 9.1 实验 α：先知文字臂（~1 GPU-日，**一行 latent 代码都不用写**）

**这是排名第一的机会（§8 的 #1），也是最快能判死整条纲领的实验。**

在开源重建的 OmniAgent 形态回路上跑 ~200 道题，按"单次调用 vs 多次调用"切开，**只对多调用子集**加一条臂：

> **把推理大脑后来会追问的全部问题，一次性交给感知工具**，让它写一份回答所有这些问题的报告——即**一个能预知未来信息需求的发送方，在文字线上能写出的最好报告**。

比较两臂准确率。这把"文字边的损失"拆成了两块：**「没预料到」的损失** 和 **「表示不了」的损失**。

**判死条件**（按触发速度）：
1. ~~多调用子集 <15%~~ → **已由 VideoAgent 的 72.2% 排除，不必再测**
2. **先知臂 ≈ 实际臂** → 预期缺口为零，损失不在这里
3. **先知臂 ≈ latent 上界** → 剩给 latent 的空间已被文字方案吃干净

### 9.2 实验 β：在 IdealGPT 上做最小 drop-in（§8.1(3) 推荐）

它是唯一一个**"latent 通道已经存在于发送方内部（Q-Former 的 32 个向量）、只是被扔掉"**的系统。三臂：

| 臂 | 交回什么 |
|---|---|
| A | ≤10 个文字 token（现状） |
| B | **32 个 Q-Former 向量**（我们的通道） |
| C | 图像本身（上界） |

工程量最小、headroom 诚实（3.2:1，不虚高）。

### 9.3 实验 γ：纯文字身份传递空测（~1 小时，判 §6.1）

GSM8K 200 条纯文字提示，三臂：

| 臂 | 做法 |
|---|---|
| A（参照） | Qwen3-8B 自己 prefill、自己解码 |
| B（朴素） | Qwen3-VL-8B **无图**prefill 同一提示 → dump 逐层 K/V → **逐字装进** Qwen3-8B → 解码 |
| C（修复） | 同 B，但先把 key 按 5e6 反旋、再按 1e6 对接收方位置重旋 |

这是**最有利的情形**（同 token 序列、同位置、位置编码精确退化、零视觉 token）。**B 若崩、C 若救不回来，§6.1 那条路线当场结束。**

## §10 追问区

### 10.1 "前缀拼接"和"加性融合"哪个更好？

不是"哪个更好"，是**目标不同**（§3.3）。前缀拼接不改接收方自己的状态，所以**可以免训练**；加性融合改写接收方的表示，所以**必须训练**，但换来"序列不加长"和"能跨模型"。

### 10.2 为什么 M-RoPE 对纯文字会退化成 1D？

M-RoPE 用 (t, h, w) 三个轴。对**纯文字 token**，这三个轴取值相同（t = h = w），三轴合起来就等价于一个轴——所以精确退化，`max abs diff = 0.0`。图像 token 才会让三轴分化（同一帧里不同位置的 h、w 不同）。

### 10.3 既然压缩比不是损失，那 §7.1 那些数还有什么用？

有用，但只能用来说**"带宽差距有多大"**，不能用来推**"损失有多大"**。**别把它当卖点**——一句"可是那些工具是照着问题写的"就能打掉。

### 10.4 为什么"更多感知反而有害"？

模型的注意力是有限资源。塞进 180 帧不相关画面，会稀释掉那 8 帧关键画面的权重。**精选 8.4 帧（60.2%）打赢均匀采 180 帧（59.6%）** 就是这个道理。

### 10.5 我们的 KV 通道会不会也踩 §6.1 的漂移问题？

**不会**——因为你的 C1 是**同一个模型**扮演所有角色，发送方和接收方权重完全一样，漂移为零。§6.1 的问题只在"两个不同模型"时才出现。

## §11 术语表

| 词 | 一句话解释 |
|---|---|
| **KV cache** | 模型算过的中间状态缓存。一张"层 × token"的表，每格装 K 和 V 两个向量 |
| **K / V / Q** | Key（我是什么，供别人找）/ Value（找到我能拿走什么）/ Query（我要找什么） |
| **prefill / decode** | 读输入的阶段 / 一个字一个字往外吐的阶段 |
| **前缀拼接** | 把发送方的 KV 接在接收方 KV 前面，序列变长 |
| **加性融合** | 在同样的位置上，用发送方的状态改写接收方自己的 K/V，序列不变 |
| **RoPE / rope_theta** | 旋转位置编码 / 它的底数；两个模型底数不同，位置就对不上 |
| **M-RoPE** | 多模态版位置编码，用 (t, h, w) 三个轴 |
| **Q-Former** | BLIP-2 里把几百个视觉 token 压成 32 个向量的模块 |
| **caption** | 给图/视频写的一句文字描述 |
| **问题条件化** | 工具在**知道问题之后**才生成输出（对比：事先算好的通用描述） |
| **互信息 I(A;B\|C)** | 在已知 C 的前提下，B 还能告诉你多少关于 A 的信息 |
| **消融 / ablation** | 拆掉某个部件看分数掉多少 |
| **headroom** | 天花板与现状之间还剩多少空间 |

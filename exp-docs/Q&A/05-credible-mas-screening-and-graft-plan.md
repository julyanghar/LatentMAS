## TL;DR（三句话，看不懂没关系，正文会讲）

1. 把 97 个"多智能体系统"按六道门槛筛一遍，**没有一个能证明"多请几个 AI"这件事本身带来了好处**——它们的好处几乎都来自别的东西。
2. 但"多智能体没用"这句话是错的。**有五种情况它真的有用**，我们要做的是认准其中一种，而不是回避这个问题。
3. 我们现在做的事（同一个模型分几个角色、轮流用文字交接、看同一张图）**恰好是那个被反复证明无效的格子**。要么换设定，要么把结论本身当成产出。

## §1 第一步：分清"员工"和"设备"

### 1.1 一个贯穿全文的比喻

整篇文档我用**一家公司**来打比方，中途不换：

| 比喻 | 对应的技术概念 |
|---|---|
| **员工** | agent（智能体）——一个会自己决定下一步做什么的 AI |
| **设备**（打印机、扫描仪） | 工具（tool）——被调用一次、返回结果、结束 |
| **交接方式**（写便条 / 口头说 / 直接把脑子搬过去） | 通道（channel）——信息在两个 AI 之间怎么传 |
| **考试** | benchmark（评测集）——一批带标准答案的题 |
| **成绩** | accuracy（准确率）——答对的比例 |

> **桥句（记住这句，后文反复用）**：
> **判断是员工还是设备，看"去掉它，公司少了一个决策者，还是少了一种能力"。**

少了决策者 → 员工。少了能力 → 设备。

### 1.2 为什么这个区分决定一切

因为它们的好处来源**根本不同**：

- **设备带来的是新信息**。一台扫描仪能看到人眼看不清的细节。你让员工再想一万遍，也想不出扫描仪没扫的东西。**这是信息论意义上不可替代的。**
- **员工分角色带来的是……可能什么都没有**。让同一个人分别扮演"方案人""挑刺人""定稿人"，他脑子里的东西并没有变多。

后面你会看到，**几乎所有"多智能体很有用"的论文，好处其实来自设备，不来自员工**。

### 1.3 三条可操作的判据

| 判据 | 设备 | 员工 |
|---|---|---|
| 有没有自己的决策回路 | 被调一次 → 返回 → 结束（被动），参数由调用方决定 | **自己决定下一步做什么**，有自己的循环 |
| 去掉它少了什么 | 少一种**能力** | 少一个**决策者** |
| 有没有自己的角色设定（system prompt） | 没有 | 有 |

### 1.4 ⚠️ 一个重要的口径分歧（用户提出，我接受）

上面这套判据是为了回答**"多请员工本身涨不涨分"**。

但如果你的研究问题是**"哪里存在两个 AI 之间的文字交接、可以换成别的交接方式"**，那么判据应该完全不同：**只要一端是 AI 的输出、另一端是 AI 的输入、中间是文字，就算一条可替换的边**——那个"设备"内部是不是也是个大模型、有没有自己的规划回路，都无所谓。

所以**两套分类学并存**，服务两个不同的问题：

| | 回答什么问题 | 计数单位 | 举例：OmniAgent 算几个 |
|---|---|---|---|
| **分类学 A**（本篇 §1.3） | 多请员工涨不涨分 | 决策者 | **1 个员工** |
| **分类学 B**（[06 文档](06-latent-collab-design-space-and-brain-tool-edge.md)的口径） | 哪里有文字瓶颈可替换 | **AI↔AI 的边** | **8 条边**（8 个"工具"全是大模型 API + 角色提示词） |

本篇用 A，因为本篇问的是"值不值得做多智能体"。

### 1.5 按分类学 A 重新归类（本轮核实过的）

**真·多员工**：Insight-V · Cola · MDocAgent · IdealGPT · PixelCraft · MMCTAgent · DART · BDoG · MAPS · LVAgent · A4VL · MACF · Mobile-Agent-v2 · SVAgent · VideoHV-Agent · LACO

**其实是"一个员工 + 一堆设备"**（常被误当成多智能体）：
- **VideoAgent（两个同名项目都是）**——见 §8.1
- **OmniAgent**——见 §8.2
- Visual Sketchpad · ViperGPT · VisProg · Chameleon · MM-ReAct · HuggingGPT · DeepEyes · Pixel Reasoner · VTool-R1 · V\* · VideoTree

**两段流水线，连员工都算不上**：Prophet · M3DocRAG · ViDoRAG

## §2 第二步：怎么"面试"一家公司

假设一家公司跟你说："我们三个人一组干活，比一个人干强 4.3 分。"

你该问什么？这一节把这些问题固化成**六道门槛**。每道门槛都在堵一个具体的漏洞。

### 门槛 E1：那"一个人"是谁？

**漏洞**：公司说"比一个人强"，但那个人可能是个实习生。
**要求**：单人对照必须用**同一个模型**（same backbone）。用一个更弱的模型当对照不算数。

### 门槛 E2：那个人被允许好好想吗？

**漏洞**：单人对照只让他脱口而出，多人组却允许充分讨论。
**要求**：单人对照至少要开 **CoT**（chain-of-thought，让模型先写推理过程再答，不是直接给答案）。更好的对照是 **self-consistency**（同一个问题让他想 5 遍，投票取多数）。

> **为什么 self-consistency 是关键对照**：三个人开会 ≈ 三次模型调用。而"一个人想五遍投票"也是五次调用。**算力差不多，所以这才是公平对手。**
> 更狠的一句话：**self-consistency 本身就是一个多智能体系统**——5 个员工、没有角色、不许交流、投票表决。你的花式协作要是打不过它，说明角色和交流一点东西都没加。

### 门槛 E3：花了多少钱？

**漏洞**：不报成本，读者看不出多人组烧了几倍算力。
**要求**：两边都报 token 数 / FLOPs（浮点运算次数，衡量算力）/ 调用次数 / 墙钟时间。

### 门槛 E4：⭐ 好处到底来自哪？

**漏洞**：这是最常见、也最致命的一个。多人组的好处可能来自四件跟"多请人"无关的事：

| 混淆源 | 白话 |
|---|---|
| (a) **模型异质性** | 三个人是三家不同公司的模型，互补 |
| (b) **外部工具** | 多人组能调扫描仪，单人组不能 |
| (c) **更多算力** | 多人组就是花了 10 倍的钱 |
| (d) ⚠️ **看到的东西更多** | **三个人一共看了 96 帧画面，那个"单人对照"只看了 16 帧** |

**要求**：必须有消融实验，把"多请人"从这四件事里分离出来。比如"把整套系统塌成一个人""把三个不同模型换成同一个模型""把工具全拔掉"。

> **(d) 在视频任务上尤其致命。** 如果多人组总共看的帧数多于单人对照，那这个实验测的**不是多智能体，是帧数**。公平版本应该是：**N 个人 × F 帧  vs  一个人 × N·F 帧**。

### 门槛 E5：模型变强之后还有用吗？

**漏洞**：好处只在弱模型上出现。
**要求**：在**测过的最强那个模型**上增益仍然为正。

### 门槛 E6：能跑吗？

**要求**：代码公开、不是空壳、用开源权重能在本地跑起来。

## §3 手把手：把六道门槛套到 DART 上

这一节用**一个真实系统的真实数字**走一遍，全篇只用这一个例子。所有算术你都可以自己按计算器验一遍。

### 3.1 DART 是什么

**DART**（[EACL 2026 长文](https://aclanthology.org/2026.eacl-long.253)，代码 [nsivaku/dart](https://github.com/nsivaku/dart)）是本次筛查里**仪器做得最好的一篇**。它的做法：

1. 三个视觉模型各自独立答题（带 CoT）
2. **它们意见不一致的地方**，就去调工具（目标检测、OCR、空间推理等）
3. 工具结果回到讨论里
4. 一个汇总模型出最终答案

一句话：**用"员工吵架的地方"来决定"该开哪台设备"**。

### 3.2 逐步表格：一道题在 DART 里怎么走

用一道 A-OKVQA（一个看图问答的考试）的题走一遍。**注**：下表是机制示意，具体某道题的中间输出我没有逐条核对；**分数是真实的**，见 §3.3。

| 步 | 谁在做 | 输入 | 内部发生了什么 | 输出 |
|---|---|---|---|---|
| 1 | 员工甲（QwenVL） | 图 + 问题 | 自己看图，写推理链 | 答案 A + 推理 |
| 2 | 员工乙（MiniCPM-o） | 同上 | 同上 | 答案 B + 推理 |
| 3 | 员工丙（Ovis2） | 同上 | 同上 | 答案 A + 推理 |
| 4 | 系统 | 三个答案 | **发现有分歧**（A/B/A） | 触发工具 |
| 5 | 设备（检测器） | 图 + 分歧点 | 跑一个目标检测网络 | 框坐标 |
| 6 | 员工们 | 加上工具结果 | 再讨论一轮 | 修正后的答案 |
| 7 | 汇总员 | 全部 | 挑最终答案 | 最终答案 |

### 3.3 ⭐ 关键数字（全部来自论文 Table 1 / 10 / 11，我逐格核算过）

同一个模型 QwenVL，在 A-OKVQA 这门考试上：

| 配置 | 白话 | 分数 |
|---|---|---|
| **CoT** | 一个人，写推理过程，答一遍 | **61.3** |
| **SC@5**（self-consistency） | **一个人想 5 遍，投票** | **63.7** |
| **3×QwenVL 辩论（共识版）** | **三个同样的人开会，看谁说服谁** | 61.9 |
| **3×QwenVL 辩论（裁判版）** | 三个同样的人开会 + 一个裁判定稿 | **62.1** |

**现在做三个减法，你可以自己按计算器：**

```
一个人想 5 遍投票，比想 1 遍好多少？   63.7 − 61.3 = +2.4
三个人开会，比一个人想 1 遍好多少？    62.1 − 61.3 = +0.8
三个人开会，比一个人想 5 遍……         62.1 − 63.7 = −1.6   ← 负的
```

> ⭐ **这三行是整篇文档的核心。**
> **"三个人开会"（+0.8）还不如"一个人想五遍投票"（+2.4）。而且直接对比是 −1.6，输了。**

再看成本（论文 Table 11，我算的倍数）：

| 配置 | 生成 token | TFLOPs | 延迟 |
|---|---|---|---|
| 一个人 CoT | 80.5 | 19.04 | 0.16 s |
| 三人辩论（裁判版） | 1196.8 | 236.83 | 27.92 s |
| DART 完整版 | 928.5 | 158.15 | 32.75 s |

```
辩论的算力倍数：236.83 ÷ 19.04 = 12.4 倍
DART 的算力倍数：158.15 ÷ 19.04 =  8.3 倍
DART 的 token 倍数：928.5 ÷ 80.5 = 11.5 倍
延迟倍数：       27.92 ÷ 0.16  = 175 倍
```

**花 12 倍算力、175 倍时间，换来 +0.8 分，还打不过省一半算力的"想五遍投票"。**

### 3.4 那 DART 论文报的 +4.3 分是怎么来的？

DART 的头条配置是**三个不同公司的模型**（QwenVL + MiniCPM-o + Ovis2）＋工具，得 **68.9**。

现在做 E4 的消融——**把三个不同模型换成同一个最好的模型**（论文自己跑了这一行，叫 "DART (Best Model)"）：

```
异质三模型 + 工具：              68.9
同一模型三份 + 工具：            65.3      ← 掉了 3.6 分
同一模型想五遍投票（SC@5）：      64.6
                                ------
真正属于"多请人 + 工具"的：      65.3 − 64.6 = +0.7
```

**结论：广告上的 +4.3，其中约 3.6 分是"请了三家不同公司的模型"，剩下 +0.7 才是结构带来的。**

### 3.5 ⚠️ 这里有个容易混的地方（两个"隔离后的数字"）

上面出现了两个不同的减法，别搞混：

| 减法 | 对比的是什么 | 数字（A-OKVQA / MMMU / NaturalBench） |
|---|---|---|
| **(a)** 整套 DART 同质化 vs 一个人想五遍 | 「角色 + 工具」这一整套，对上「采样投票」 | **+0.7 / +0.8 / +0.7** |
| **(b)** 三人辩论 vs 一个人 CoT | 纯粹的「开会」，对上「一个人想一遍」 | **+0.8 / +1.5 / +0.7** |

两个都对，只是问的问题不同。**我早前的文档把这两个混成一个，已更正。**

### 3.6 最后一击：这些数字有意义吗？

DART 的评测集是 1135 题和 900 题，**单次运行、没有误差棒**。

一个粗略但够用的估算：这种规模的单次运行，**标准误大约 1.4–1.6 个百分点**。

> **而隔离出来的效应是 +0.7~+0.8 分——比它自己的测量噪声还小。**

### 3.7 DART 的六门槛成绩单

| 门槛 | 结果 |
|---|---|
| E1 同 backbone 对照 | ✅ 有，四个模型都有 |
| E2 强对照 | ✅ **全场最好**：CoT + Self-Refine + SC@5 + 两种多智能体基线 |
| E3 算力账 | ✅ **少见地完整**：token / TFLOPs / 延迟都报了 |
| E4 隔离"多请人" | ✅ **全场最完整**——**而结果是不利于多智能体的** |
| E5 强模型上还有用 | ❌ 最强只测到 7–9B；32B 只当基线没当队员 |
| E6 真开源 | ✅ 代码真、权重开放 |

**5/6 通过，唯一挂在 E5。而它自己的 E4 行拆掉了自己的头条。**

## §4 把门槛套到 97 个系统上

### 4.1 规模

六路筛查扫了 **97 个系统**，其中 **48 个判为真·多员工**，对最接近通关的 8 个逐篇深挖（读 PDF/HTML 原表），最后三条对抗裁定。

### 4.2 总裁定

> **没有任何一篇已发表的多模态多智能体系统，能证明它相对"同模型 + 同等提示"的单智能体的增益是成立的（established）而不是被混淆的。**

反过来，**被确立的是那个否定结论**：多模态里隔离出来的同 backbone 多智能体，**最好也只值 +0.1 ~ +2.4 分，且在最强的模型上为负**。

### 4.3 三个最接近通关的（各有可用之处）

| | 系统 | 关键数字 | 卡在哪 |
|---|---|---|---|
| **①** | **Orchestra-o1**（全模态）<br>[2606.13707](https://arxiv.org/abs/2606.13707) · [zfkarl/Orchestra-o1](https://github.com/zfkarl/Orchestra-o1) ✅ · 权重 [Karl28/Orchestra-o1-8B](https://huggingface.co/Karl28/Orchestra-o1-8B) ✅ | **同模型 + 同工具**的对照：53.9 → **72.8（+18.9）**；开源臂 Qwen3-8B 12.5 → 26.3（**纯框架，零训练**）。⭐ **模型越强增益越大**——和常见的"只在弱模型上有效"正好相反 | 没有等算力对照（没有 SC@k），没有"减少一个 agent"的消融 |
| **②** | **PixelCraft**（图表/几何）<br>ICLR'26 · [microsoft/PixelCraft](https://github.com/microsoft/PixelCraft) ✅ | ⭐ **全场隔离得最干净的数字 = +3.1**。它自己造了对照：**同样的提示、同样的工具、同样的像素，只是把多个角色换成一个 planner**，65.0 vs 68.1 | 推理模型**全闭源**；且它自己的"辩论/协调"对照在 **18 个格子里有 13 个低于单人 CoT**；论文自报的 +9.5 是拿"直接答题"当对照算的，**对 CoT 的诚实差值只有一半** |
| **③** | **RadAgents**（胸片）<br>MIDL 2026 | ⭐ **消融做得最好：两条单人臂，同一个 Qwen3-VL-8B** —— 光 ReAct 68.0 / ReAct + **把诊断流程当提示词给它** 71.0 / 全系统 74.6。→ 对朴素单人 +6.6，**对"结构化提示"这条控制臂只剩 +3.6** | **没有代码** |

> **③ 那条控制臂值得单独说**：几乎没人做过。他们把"多个专科医生分工"这件事，和"只是告诉模型按 ABCDE 流程走"分开了——**光是给个流程提示词，就拿到了 6.6 分里的 3.0 分。**

### 4.4 一个被推翻的"最佳候选"

我原本押注 **Mobile-Agent-v2 的 +30%** 是最干净的对照（同作者、同模型、单人版 vs 多人版）。**核完全错了**：

- 它是**跨版本整系统对比**，同时变了四件事；其中贡献最大的 "memory unit" **是个数据结构，不是员工**
- 多人版每步 **≥3 次模型调用，论文完全没报**
- 消融表**每一行都开着 planning agent**，所以"多请人"从未被隔离
- 论文摘要自己把胜因归给 **token 序列长度**，不是协作
- ⭐ **第三方反例**：[Mobile-Bench-v2](https://arxiv.org/abs/2505.11891) 在 **800 条指令**上重测，**多智能体版在全部六个模型上都输给单智能体版**，差距 1.1–41.6 分
- 原始 +30% 里，效应主要由**基线崩掉的那一侧**（中文场景单人版只有 2/10）撑起来

## §5 那什么时候"多请人"真的有用？

不是没用，是**只在五种情况下有用**。这一节把它们列全。

### 5.1 先看三种曲线

"加人/加轮次"的效果不是一条曲线，是**三条**，由两件事决定：任务有没有便宜的对错信号 + 单人已经多强。

| 形状 | 什么时候出现 | 长什么样 | 会超过单人吗 |
|---|---|---|---|
| **A：升 → 饱和** | 独立采样 + 聚合（不交流，只汇总） | [Wunderlich 等](https://arxiv.org/abs/2605.01566)（**唯一把多智能体和采样投票画在同一根算力轴上的论文**）：CoT **64.3** → 采样投票 **68.7** → 辩论 **70.0** → **MoA 71.4**（20 倍算力时仍在上升） | ✅ **会**。等算力下 MoA 比采样投票高 **+2.7**。⭐ **而且它的 MoA 是同一个模型当提议者——不是异质性** |
| **B：倒 U，尾巴掉到单人以下** | 同样的人、同样的输入、只增加**讨论轮数** | L²-VMAS：84.8 → **86.6（第 3 轮）** → 第 6 轮起跌破单人 → **第 10 轮低 2.6 分**，token 从 557 涨到 16,840（30 倍） | ❌ 不会 |
| **C：从一开始就平或降** | 长流程、要用工具的任务 | ["Do More Agents Help?"](https://arxiv.org/abs/2606.05670)：单人 74.12 分 / 27.4K token；**6 个多智能体系统里 5 个输**；某个系统**花 3.9 倍 token 低 5.3 分** | ❌ 不会 |

### 5.2 ⭐ 一个决定性的反例：多模态上确实有 20 轮单调上升的曲线

**ViF（[2509.21789](https://arxiv.org/abs/2509.21789) v3）Figure 7**（验证者直接下载图片读的）：

| 模型 | 第 1 轮（作者明说 ≡ 单人） | 5 | 10 | 15 | 20 |
|---|---|---|---|---|---|
| Qwen2.5-VL-7B | 41.7 | 50.4 | 52.5 | 53.7 | **54.7（+13.0）** |
| LLaVA-NeXT-7B | 42.3 | 49.4 | 51.1 | 52.0 | 52.4 |

**六个模型的曲线全部单调、20 轮不回落。**

**但关键在这里**：ViF 是**训练过通道**的。它自己的**未训练**对照恰恰是倒 U——FarSight 42.5→47.5→47.4→45.9→**44.0**。

> ⭐ **换掉交接方式，倒 U 就变成单调上升。** ViF 用"视觉 token 流"、L²-VMAS 用"latent 记忆"都做到了，**而且都是花更少 token 赢的**——所以原因是**通道**，不是算力。

### 5.3 五种真正有效的机制（+ 一个假象）

| | 机制 | 白话 | 证据 |
|---|---|---|---|
| (a) | **看得更多** | 三个人分工看不同的画面 | MACF、MECoBench |
| (b) | **人不一样** | 请三家不同公司的模型 | DART：换成同一个模型掉 3.6 分 |
| (c) | ⭐ **交接方式被训练过** | 不是写便条，是训练出一条专用通道 | L²-VMAS、ViF —— **且都是花更少 token 赢的** |
| (d) | ⭐ **有个外部裁判挑答案** | 生成一堆，让一个训练过的裁判选 | **VisualPRM**：同一个模型、同一张图、**没有训练过的通道、没有额外感知**，靠裁判**单调升到 N=128**：32.8 → **44.0（+11.2）** |
| (e) | ⭐ **纯粹多采样再投票** | 就是 self-consistency | 同一张表里**什么都不训练**的采样投票：32.8 → 41.0，**128 倍扫描里从未跌回单人以下** |
| **(f)** | ⚠️ **假象：串行自我修订** | 看起来是"讨论"，其实是"自己再想一遍" | **[Ringelmann 定律](https://arxiv.org/abs/2606.02646)**：**30 个辩论 agent 的有效样本量只有 1.12**；且其**噪声安慰剂与自我修正同步**——说明同质队里被归给"辩论"的好处，其实是重新评估，**不用第二个人就能以 10–45 倍更低成本买到** |

> **真正 durably 失败的是精确的这一格**：**同样的模型 + 同样的输入 + 纯文字交接 + 只增加讨论轮数**。倒 U 就住在这里。
> **而这正是本项目 C1 的设定。**

### 6.3 ⚠️ MACF 那个净零，很可能是稻草人

【核实，在 transformers 4.57.1 源码层逐行确认】

> **位置编码坍缩比原以为的严重得多。** 不只是"默想步塌成 [0,0,0]"，而是**第 2 到第 M 个 agent 的整段提示（含全部视觉 token）都不会调用 `get_rope_index`，三个位置轴退化成同一个平坦序号、且从 0 重启。**

**位置编码（RoPE）是什么**：模型靠它知道"这个词在句子的第几个位置"。多模态模型（M-RoPE）用三个轴：时间 t、高 h、宽 w。如果位置全塌成 0，模型就以为所有 token 都在同一个位置——**不报错，但结果全乱**。

而你的 B1 模块（`mrope_takeover.py`）已经修好了这个，两级验收 top-1 100%。

**第二条稻草人证据**：MACF 表里的 "784 KV-Cache" 可以反解——Qwen3-VL 在 224px 下每帧 `(224/16/2)² = 7² = 49` 个视觉 token，**784 ÷ 49 = 16 帧**。也就是说它的 `LatentMAS*` 基线**可能根本没拿到额外的那 6 段帧**。

> ⚠️ **由此产生一个必须自己测掉的歧义**（我早前的读法要更正）：
> - **读法 A**：96 帧 + KV 通道 = 打平 → 通道浪费了 6 倍帧
> - **读法 B**：**16 帧 + KV 通道 = 打平 → 完全符合你的 X≈U，KV 通道无损，MACF 的增益全部来自"多给了 5 倍帧"而非通道**（对你有利，且与你自己的数据一致）

### 6.4 好消息：视频上的位置编码几乎是免费的

【核实，读 transformers 本地源码】**Qwen3-VL 根本没有时间缩放因子**：

> `modeling_qwen3_vl.py:923` 的原话："Different from the original implementation, Qwen3VL use **timestamps** rather than absolute time position ids."
> 紧接着的 `:926-928` 把每帧拆开，并把时间轴 t **强制设为 1**。

**白话**：在 Qwen3-VL 眼里，一段视频就是**一串各自独立的单帧图片，每帧前面插一个文字时间戳**。时间轴往前走，靠的是那些文字 token 占位置。

→ **你现有的图像位置追踪模块几乎可以直接用到视频上，不需要新的时间轴逻辑。**

### 8.2 OmniAgent 呢？

仓库为真（[KD-TAO/OmniAgent](https://github.com/KD-TAO/OmniAgent)，HTTP 200，18 个文件），但读代码就清楚了：

```python
# agent_builder.py —— 一个 agent，8 个 tool
from langchain_classic.agents import AgentExecutor, create_openai_tools_agent
# config.py —— 大脑和工具全是闭源 API
```

**⚠️ 引用纪律**：它的 +10~20% 里混了**模型异质性（4 个前沿模型）+ o3 大脑本身更强 + 工具带来新证据**三件事，且**没有同模型对照**。只能说"工具编排 + 前沿模型组合有用"，不能说"agent 化对全模态有用"。

### 8.3 "self-consistency 是多智能体"这句话是不是文字游戏？

不是。它是**判据**，不是修辞：5 次独立采样 + 投票 = 5 个员工、无角色、无交流。你的花式协作**多出来的只有"角色"和"交流"**这两样。打不过它，就说明这两样没加东西。

### 8.4 为什么"更多感知反而有害"？

这个反直觉的现象在 §5 和 [06 文档](06-latent-collab-design-space-and-brain-tool-edge.md) 都出现了。直觉解释：模型的注意力是有限资源，塞进 180 帧不相关画面，会稀释掉那 8 帧关键画面的权重。**精选 8.4 帧（60.2%）打赢均匀采 180 帧（59.6%）** 就是这个道理。

### 8.5 我们的实验够大吗？

你每格 n=800/798，配对 McNemar 检验 + 报告 discordant 对数。检出力约 5 个百分点。

⚠️ **但要吸取 DART 的教训**（§3.6）：**必须把"效应量 vs 检出力"写在表旁边**。如果你测出的效应比自己的噪声还小，那张表就没有说服力。

## §9 术语表

| 词 | 一句话解释 |
|---|---|
| **agent（智能体）** | 会自己决定下一步做什么的 AI。比喻里的"员工" |
| **tool（工具）** | 被调用一次、返回结果、结束。比喻里的"设备" |
| **backbone（骨干模型）** | 系统底下用的那个大模型本体 |
| **CoT** | chain-of-thought，让模型先写推理过程再给答案 |
| **self-consistency (SC@k)** | 同一问题采样 k 次，投票取多数 |
| **Best-of-N (BoN)** | 生成 N 个候选，用一个打分器挑最好的 |
| **PRM** | process reward model，给推理的**每一步**打分的模型（对比：只给最终答案打分） |
| **ablation（消融）** | 拆掉系统的某个部件，看分数掉多少，用来判断这个部件值多少 |
| **FLOPs** | 浮点运算次数，衡量算力 |
| **KV cache** | 模型算过的中间状态，缓存下来避免重算。详见 [06 文档](06-latent-collab-design-space-and-brain-tool-edge.md) §1 |
| **prefill / decode** | 读输入的阶段 / 一个字一个字往外吐的阶段 |
| **RoPE / M-RoPE** | 位置编码；M-RoPE 是多模态版，用 (t, h, w) 三个轴 |
| **McNemar 检验** | 配对二值数据的显著性检验，适合"同一批题、两种方法"的比较 |
| **discordant 对** | 两种方法答案不一致的题数。这个数太少，结论就不可信 |
